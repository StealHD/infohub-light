# Agent Workspace UI Contract

## 1. Routes and runtime continuity

- `/agent` owns the full conversation workspace. `/agent/tasks` and `/agent/artifacts` keep that conversation mounted and open an inspector; `/agent/skills`, `/agent/automations`, and `/agent/examples` retain the session sidebar while replacing the center with a complete resource page. `/agents` remains Inscope assistant-connection management.
- Managed Service connection requires an explicit first successful connect in each browser. Only then may that user auto-connect on later login or refresh; the preference is user-isolated and connection never changes the current route. An explicit recovery action may discard only the local session selection and create a personal session, preserving remote history and binding.
- The authenticated app shell owns one ordinary `useOpenClawChat` lifetime after the first Feed/OpenClaw activation. The runtime remains mounted across Feed, Saved, History, Subscriptions, `/agent/**`, `/agents`, account, and settings routes until logout, user change, explicit disconnect, or shell unmount. Navigating from the compact Feed rail with “在 Agent 工作台打开” changes only the route: it does not send, create a session, replace the ordinary socket, clear the draft, or abort a run.
- The compact Agent rail is limited to Feed, Saved, and History. Subscriptions keeps the ordinary runtime mounted but has no compact rail. Full Agent routes consume the same `OpenClawWorkspaceRuntimeProvider` and `WorkbenchAgentContext` without mounting another ordinary Gateway client.

## 2. Dual workspace layout and navigation

- Agent is not an ordinary Inscope navigation row. The top-left product switcher owns two peers: `Inscope — 订阅、阅读与追踪` and `OpenClaw — 对话、执行与自动化`. Desktop uses a Popover in the sidebar; mobile uses a bottom Sheet from the page header. It persists only the latest allowlisted route for each user and workspace. Switching is SPA navigation only and cannot send, create a Session, replace the ordinary socket, clear a draft, or stop a run.
- Inscope keeps 信息流、收藏、历史、订阅 and management routes. Mobile primary navigation is 信息流、收藏、订阅 plus 更多; OpenClaw is entered through the product switcher. OpenClaw replaces the whole navigation shell with new conversation, recent authorized sessions and Worktree tasks, Skills, Automations, examples, and the shared account menu. Assistant connections remains in Inscope management.
- At 1024 px and above OpenClaw uses one fixed 232 px session sidebar and one center workspace. At 1440 px and above an explicitly requested 360 px Context, Tasks, or Artifacts inspector docks on the right; it is closed by default and leaves at least 720 px for the center. There are no workspace resizers or persisted rail widths.
- At 768–1023 px session and inspector surfaces are left/right Drawers. Below 768 px both are bottom Sheets and the conversation composer preserves the viewport safe-area inset. No mode introduces horizontal page scrolling.
- The center Session Header contains only title, trusted branch, a compact connection/run status, and responsive workspace/session controls. Below 768 px, Context, Tasks, Artifacts, and theme live behind one More Sheet; desktop inspector icon actions expose tooltips. Conversation content is approximately 860 px wide and the Composer is at most 920 px. Ordinary messages are unframed; only public tool state, errors, and confirmations use local surfaces. The compact Feed Agent keeps its existing conversation variant and geometry.
- HeroUI Pro is only a hierarchy and composition reference. `AgentWorkspaceLayout`, conversation, list, status, empty, upload and Sheet behavior use HeroUI v3 OSS through the repository design system; no Pro code, package, asset or key enters the repository.
- The Session Header reuses `PageHeader` and the shared inset glass geometry. Its inset belongs to the inner conversation/resource scroll region, never the workspace root. Session headings and rows share a readable-title projection; machine labels and raw keys are hidden without rewriting existing server metadata. A compact semantic connection indicator replaces duplicated status text; resource routes use their own page title. “使用示例” lives in workspace navigation and opens the read-only `/agent/examples` resource page with steps and expected outcomes; it never issues RPCs or inserts demonstration records into real resource lists.

## 3. Sessions and Worktree tasks

- Navigation is a separate Gateway-authorized directory, never an ownership guess from labels. The rail shows at most three single-line rows: current plus the two most recently active other non-archived sessions. Status is inline; a keyboard/touch-operable details Popover exposes the full title.
- Resource navigation reuses the same workspace error-boundary identity and sidebar DOM; route recovery must not remount the rail for Skills, Automations or Examples.
- Selecting an already visible session preserves recent-activity order and navigation geometry. Switching feedback uses a non-layout live status, and the new-conversation button shows creation pending only for its own action. Selecting a session outside the three visible rows replaces only the least-recent slot so the current session remains visible.
- “全部会话” opens a searchable 50-row paged directory, with non-archived sessions by default and an archived-only filter. Follow server offsets beyond 200 rows. Directory pages never define Tasks/Artifacts scope. Results are isolated by user, Gateway, connection generation, search, archive filter and offset; stale responses cannot replace the current scope.
- Explicit navigation verifies exact preview, directory membership, Agent and described Session before activation; synchronous exclusion covers the entire switch. New conversations retain prior local transcript records. Refreshing or browsing history never sends, creates or renames a session.
- New ordinary sessions omit an explicit label so Gateway can generate a title from the first user message. Authored titles take precedence; pending/failed generation uses a short visible-message excerpt, then a dated name or “新对话”. No bulk AI renaming of old sessions occurs.
- The connection form keeps fields and full-width actions on the same inline edges; workspace actions stack below 640 px and share equal columns above it. Pending states retain their geometry and errors use the shared body-text role.
- The composer groups context usage, the visible model name and effort pill immediately before Send, with attachments at the left. The reference-style effort pill opens a model selector and a stepped reasoning slider. Only Gateway-supported effort levels appear, excluding off/none/auto. An inherited default is displayed only when supplied by Gateway; reset selects that explicit default, never an invented value. Changing a level commits on release, excludes concurrent updates, and restores the confirmed value after failure. Model/reasoning slash commands open the same surface. The lightning toggles Fast independently of effort, with a pressed state and a short usage reminder. Only enabled Fast drives slider particles. Successfully entering Ultra uses the same transient reminder for increased token use, even when Fast is off; failed changes show no usage reminder. The choice applies to the next send and original retry snapshot under the Gateway contract; no message is sent by toggling, and running or changing sessions disables it. Exact-session Gateway defaults are restored on connection; new sessions and account/Gateway changes clear the local override. The tooltip explains potential extra usage without promising a fixed speed multiplier. The reference skin adds no voice or approval capability.
- Account actions reuse the Inscope menu and authenticated logout cleanup. Inspector open/close follows UI-INT-06; workspace composer geometry and right-aligned model/reasoning controls use the component matrix.

- A connection epoch establishes one trusted root Session. The Tasks/Artifacts resource scope contains the root, current Session, its verified ancestors/siblings, and verified descendants whose exact `parentSessionKey` chain reaches that root. Cycles, orphans, and label/name inference are ignored. A new conversation or an explicitly selected unrelated authorized session establishes a new root; switching within the tree does not.
- Session switching is unavailable while the current session is sending, running, stopping, or updating. Switching first verifies the target runtime and preserves the existing ordinary Gateway connection; a failed switch leaves the current conversation active.
- The workspace supports chat and Skill invocation; Worktree creation and retry are unavailable. Remove the sidebar and shortcut creation surfaces. Legacy controller methods reject locally without Gateway requests; existing sessions and history remain readable.
- There is no `tasks.create` UI. Any future Agent-originated `suggest_task` payload remains inert until a separately specified, server-verifiable confirmation-card protocol exists; generic tool events can never create a Session or Worktree.

## 4. Tasks and Artifacts

- Tasks are queried for the trusted root Session tree, at most 50 visible rows, with status filtering, details, and a local cancel confirmation. List/detail/cancel responses must repeat the requested Session/Task provenance. A verified task event refreshes the page; otherwise polling is limited to a visible page with a queued or running task and runs every two seconds, and event reliability resets after reconnect or root change.
- Artifact list/get/download always carries exactly one explicit session, run, or task provenance. Content and URLs travel browser-to-Gateway only and never enter Service API, Service storage, transcript, or persistent browser cache.
- Inline preview allows safe raster images and valid UTF-8 plain text, Markdown, JSON, and code up to 2 MiB. HTML, SVG, unknown MIME, or larger content is download-only. Base64 downloads are capped at 50 MiB; temporary URLs must be unexpired HTTP(S) at the normalized current Gateway origin. Object URLs are revoked after use.

Opening a current session from Skills/Automations/examples returns to `/agent` without a Gateway switch. Opening another session navigates only after a successful exact-session switch; failure retains both session and route. Creating a new conversation also returns after success.

## 5. Skills, Automations, and admin isolation

- In managed Service mode, Skills, details, composer `@`, and `/skills` contain only the workspace allowlist. The page title and count say “已开放 Skills”; an empty list says “管理员尚未开放 Skills”. Owner/Admin alone see “管理开放范围”, where a confirmed dialog reads the full safe catalog, searches and filters by all/allowed/closed, and submits a revision-checked checklist. Member sees only allowed entries; Viewer remains read-only. Account, binding, or policy revision changes invalidate rows, details, selection, and late responses.
- “已开放” and “可使用” are separate states. An allowed Skill can remain disabled, unavailable to the current Agent, or blocked by missing binaries, environment names, configuration, OS, or tool permission. Details show only public requirements, never values or paths; unavailable entries cannot be selected. Refresh failure retains trusted current-revision rows and offers retry. A pending/failed save never shows success, preserves the requested checklist, and exposes retry while new chat submission remains unavailable.
- In direct Gateway mode, Skills status is read through the ordinary connection. Management remains limited to user-supplied ZIP archives, 20 MiB or the smaller Gateway limit, browser SHA-256, sequential 512 KiB chunks with verified offsets, commit-before-install, and explicit confirmation for replacement. The page only displays missing environment-variable names and never accepts their values.
- Legacy Cron lists and run records use Gateway offset pagination; prompt editing preserves the complete text and whitespace (over 400,000 characters fails explicitly). Create binds the verified current Agent; update preserves the stored Agent. Unbound legacy jobs remain readable and may be stopped or deleted, but cannot be edited, enabled or run. Shared Service connections do not expose temporary Gateway administration.
- Automations support list/status/runs, disabled-by-default create, edit, enable/disable, delete, and run-now. The only payload is `agentTurn`; schedules are one-time, fixed interval, or Cron with an explicit IANA timezone; sessions are isolated and delivery is none. The UI never enables the Gateway scheduler itself and exposes no webhook, external delivery, shell, secret, or implicit enablement.
- Skill writes and Cron management use a separate memory-only admin controller. A write intent opens a temporary authorization Modal/Sheet instead of occupying the page; successful authorization only unlocks actions and never replays the original write. The controller publishes connecting/authorized/expired/disconnected/failed state, creates a temporary device/socket requesting exactly `operator.admin`, routes no chat events, exposes only the fixed Skill/Cron method allowlist, never reconnects, and closes on page unmount, Gateway URL change, network close, explicit destroy, connection failure, or ten minutes idle. Late connect completion is immediately destroyed. Token, private key, device token, chunks, URLs, and responses are not written to Service, logs, telemetry, `localStorage`, `sessionStorage`, IndexedDB, or the ordinary event router.
- Before browser-direct admin authorization the user must affirm that the Gateway is personal or belongs to an independent trust domain. Shared Service connections never expose this temporary Gateway authorization; their Owner/Admin Skill policy action uses the Service API. A cleanup warning directs the user to OpenClaw device management if temporary-device removal is not confirmed.
- Task cancellation on the ordinary connection requires a separate independent-trust-domain confirmation for the current connection. It is memory-only, is cleared by reconnect or URL change, and unlocks but never replays the original action.

## 6. Capability and failure states

- OpenClaw 2026.8.1 is the fixture baseline, not a version switch. Runtime availability comes only from exact `hello.features.methods`; root/snapshot/malformed method lists are ignored. Every response is strictly projected before it reaches a page. A method that is absent or not yet proven remains `unsupported` and cannot reach a write request.
- Connection generation and Session navigation epochs guard every asynchronous continuation. Stale operations cannot bind a Session, replace transcript/resource content, write the credential Vault, or overwrite loading/error state; queued Vault writes preserve the latest intent.
- Conversation, Sessions, Tasks, Artifacts, Skills, and Automations independently render loading, empty, unavailable, unsupported, forbidden, and failed states. A resource failure retains prior valid content and cannot clear the transcript, draft, session, or another resource view.
- The conversation exposes only public message content and fixed public execution statuses. Private reasoning, raw tool arguments/results, credentials, paths, untrusted errors, and confirmation material never render or persist.

## 7. Shared Composer shortcuts

- Both workspace and compact Feed composers retain their TextArea, image and model controls. At the caret, `@` or `/` after whitespace or at the start opens a non-modal, upward-first design-system suggestion surface; embedded email/URL/path symbols do not trigger. Suggestions never take textarea focus. Arrows select, Enter chooses without sending, Escape or an outside press dismisses without changing the draft, and Tab retains normal focus traversal; an outside press does not override its new target. IME composition and Shift+Enter retain existing behavior.
- `@` groups Skills and already-attached material titles. Material selection inserts a bounded readable title without changing attachments. `/` lists only `skills`, `new`, `model`, `reasoning`, `status`, and `help`. Executing a command replaces suggestions with one temporary composer-anchored operation panel; it never adds transcript entries or sends a model prompt. Skills, status, help, model/reasoning choices and new-session confirmations remain local, preserving drafts and existing capability, trust, idempotency and pending guards. Close and Escape restore input focus; pressing outside dismisses the panel without overriding the newly pressed target's focus. Successful selection or cancellation dismisses the panel. A new command replaces the prior panel. The panel is isolated by current user/Gateway/generation/session, never persisted or included in model context. An exact known command also dispatches locally through Send after dismissal or trailing whitespace; unknown text remains ordinary chat.
- Menu and panel titles use readable action names; only Help includes the `/help` hint. Existing supported slash spellings still dispatch locally. The retired `/worktree` command only explains unavailability and cannot create a task.
- One removable selected Skill follows the user's draft across workspaces. Selection is not execution; source-snapshot mode rejects simultaneous Skill selection. Unavailable entries explain their disabled state. Invocation proof, directory isolation, send-time verification, and private-history projection are owned by the Gateway contract. Menu geometry is owned by the component matrix.

### 个人接入状态（阶段 2）

`/agents` 与服务端聊天设置复用个人接入卡；查询按登录 userId 隔离，刷新保留已加载内容。绑定验证、聊天实际连接、本人内容授权、提醒和通知分别展示，未验收不显示已完成。未绑定或服务端配置不可用时禁用连接并说明管理员修复入口；连接失败保留当前草稿。

## 个人信息提醒

列表使用紧凑任务卡：状态筛选和已加载范围搜索不触发写操作，卡内仅名称、状态、频率、下次处理时间及当前页面内的测试状态；完整配置按需进入 `ResourceDetailsPanel`。宽屏详情可拖动并按账号记忆独立宽度，任务列表至少保留 640 px；空间不足改用 Drawer/Sheet，并保持关闭后的焦点返回。新建也使用该面板；一次只编辑一条，写操作完成前不切换或关闭。筛选、刷新、拖动及详情标签切换不卸载已打开的编辑器；不将归档或持续任务伪装为“已完成”。

`/agent/automations` 默认呈现 Service 的个人提醒列表；旧 Gateway Cron 保留在 `?advanced=cron`，使用原临时管理授权。详情默认“概览”，与“测试”“运行记录”分开；概览将四行描述、前两个来源、模型、频率和通知目标收敛成摘要。只有进入编辑才显示表单，来源通过可取消的独立搜索多选面板确认，模型选择直接显示，触发/通知配置分组展开；保存操作常驻，退出编辑保留草稿，保存不等于启用。统一自然语言描述不区分关键词与语义模式；四种触发的参数逐项展开，模型及推理选项来自本人目录，失败保留原选择。新建直接进入编辑模式。已归档任务提供恢复入口，恢复后是未确认草稿而不是启用态。列表、卡片、运行查询按 userId 隔离。未保存规则配置按 userId、ruleId、version 存入 sessionStorage，旧版本不自动覆盖新版本。

测试初始只显示规则版本、已选文章数和选择/开始操作。文章在独立面板中从当前最新 Feed、且属于任务来源的条目里搜索和分页选择，每页 10 条；取消不改变选择，确认形成本次快照。测试使用已保存版本，未保存修改必须先保存；提交中、排队、分析、额度等待、完成、失败和结果未知分别呈现，只显示服务端真实计数，不伪造百分比，且始终说明不发送通知。页面内测试状态按 userId、ruleId、version 隔离并在详情外轮询；关闭或切换任务后可从列表状态回到同一次测试，但浏览器刷新不承诺恢复，也不自动重提。综合结论优先，判断依据、逐篇结果和运行详情默认折叠；接口不支持取消测试时不提供取消操作。

聊天中仅 assistant 的规则引用可触发可信卡读取，最多三张；当前账号无权读取时不展示可操作内容。新建与示例仅保存草稿；测试展示版本及不发送说明；启用必须保存后再单独确认。判断与通知分别展示，未知投递不得显示已发送或提供自动重发。真实通知回执仍按本轮用户要求保留待验收。
