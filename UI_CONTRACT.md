# Inteliscope UI Contract

## 1. Authority

This file is the sole source of truth for production UI technology, visual language, responsive behavior, and browser acceptance. `PLAN.md` records delivery state, `DECISION_LOG.md` records durable choices, and `tests/test_impact_map.json` selects verification; they must reference this contract rather than restate its visual rules. API fields, authorization, query ownership, and error envelopes remain governed by `API_CONTRACT.md` and existing application tests.

## 2. Production UI system

- Production uses React 19, HeroUI v3, Tailwind CSS v4, Lucide icons, and the self-hosted Noto Sans SC variable font.
- `frontend/src/design-system/**` owns the semantic theme, approved component exports, icon exports, and React Router bridge. Production application and feature code import UI components through this boundary and do not import `@heroui/*` directly.
- `AppBootstrap` mounts exactly one `DesignSystemProvider`, inside `BrowserRouter` and outside production routes. It remains inside the existing `QueryClientProvider`; Query Client, authentication, `ServiceApi`, caches, permissions, and query keys retain their existing lifetimes.
- MUI, MUI Icons, and Emotion are not production dependencies or source technologies. `frontend/src/ui/**`, the MUI prototype, and page-level legacy visual CSS Modules do not exist.
- The sole direct-HeroUI feature exception is the fixed-data development preview at `frontend/src/features/workbench-heroui/**`.

## 3. Visual language

- Production exposes exactly two application color modes: dark and light. Dark is the compatibility default and preserves the current graphite appearance; a shared icon-only control at the top-right of authenticated headers and the login surface changes the browser-persisted choice. The HTML bootstrap sanitizes and restores the same `inteliscope.ui.theme.v1` preference before React starts, so refresh does not flash the other mode and later operating-system appearance changes do not override the explicit choice. Color mode remains separate from the `graphite-purple` theme-family identifier so a future family can be added without changing the two-mode control. Both modes use quiet neutral canvases, layered semantic surfaces, restrained purple accents, semantic separators, and visible accessible focus rings; raw palette values belong only in design-system theme assets.
- The entire production application uses one system UI font stack: `-apple-system`, `BlinkMacSystemFont`, SF Pro where available, `PingFang SC` for Chinese on Apple platforms, then the self-hosted `Noto Sans SC Variable` and system sans-serif fallbacks. Routes and feature components may not define a competing font stack.
- Typography has exactly eleven semantic roles. Their implementation lives in `frontend/src/design-system/theme.css`; business code selects a role and never recreates its size, weight, line height, or letter spacing.

| Role | Size / line | Weight | Intended use |
|---|---:|---:|---|
| `type-display` | 24 / 32 px | 600 | standalone authentication or dedicated display titles |
| `type-section-title` | 18 / 26 px | 600 | major page sections |
| `type-page-title` | 16 / 24 px | 600 | workbench headers, dialogs, card section headers |
| `type-card-title` | 16 / 23 px | 600 | Feed, saved, and history card titles |
| `type-body` | 14 / 22 px | 400 | summaries, descriptions, notices, ordinary content |
| `type-chat` | 13 / 20 px | 400 | compact OpenClaw user and assistant message bodies |
| `type-control` | 13 / 20 px | 500 | buttons, toolbar values, navigation and menu actions |
| `type-meta` | 12 / 18 px | 400 | source, time, counts and technical metadata |
| `type-label` | 11 / 16 px | 500 | navigation group labels and compact composer labels |
| `type-micro` | 10 / 14 px | 500 | count badges and mobile navigation captions |
| `type-prose` | 14 / 26 px | 400 | expanded captured body text |

- Elements in one functional group use the same semantic role. In particular, the Feed view bar count, order control and filter control all use `type-control`; source and time share `type-meta`; channel/topic metadata uses `type-meta` or `type-micro` according to density.
- Compact semantics are intentionally split instead of being expressed by one global Chip treatment. `StatusIndicator` represents running, connection, health, success, warning and failure with a distinct glyph and tone and never relies on color alone. Its default renders at least 12 px visible text; high-density source health, run records, global schedule, Agent connection/pairing and OpenClaw-header placements may opt into `iconOnly`, which keeps the full accessible name and reveals the same text from an above-anchored Tooltip on hover or keyboard focus. Notices, Toasts, dialogs, run traces and actionable recovery copy retain visible text. `MetaTag` represents channel, topic, format, scope and permission as neutral metadata; `CountBadge` represents only a count; `RemovableTag` is reserved for editable state, is keyboard focusable, has a remove target of at least 28 px and exposes pending/disabled state. Feature code does not globally resize every Chip or use a status pill for ordinary metadata.
- Production business code may not use Tailwind font-size, font-weight, line-height, or letter-spacing utilities (`text-xs`, `text-[…]`, `font-*`, `leading-*`, `tracking-*`). The executable UI contract rejects them. Alignment and semantic color utilities such as `text-left` and `text-muted` remain allowed.
- Radius scale: 16 px panels, 14 px cards, 10 px controls, and 8 px small controls. Static surfaces use contrast and a thin separator rather than glow or heavy shadow.
- Purposeful transitions run for 120–220 ms. Reduced Motion makes nonessential transitions effectively immediate while preserving loading indicators' understandable state.
- A hard refresh paints the graphite background and the last known navigation, header, Feed, and eligible docked Agent geometry directly from the HTML bootstrap shell. React removes that shell only after the authenticated route has committed; the root, shell, and page may not use an opacity entrance or replay a page-level entrance animation during takeover.
- Initial Feed and Agent reads use fixed-geometry design-system Skeletons that preserve the real column widths and closely approximate the loaded block heights. Loading motion is an opacity-only 1,400 ms restrained breath with no traveling shimmer. When data becomes available, only the local data layer transitions: Skeleton opacity exits in 120 ms and content reveals over 200 ms from `translateY(4px)` to rest. Reduced Motion makes all three effects immediate.
- Feature code does not define raw colors, shadows, radii, transition durations, or new page-level CSS visual systems. Native layout values may be used only where the static contract explicitly permits them.
- Loading, empty, degraded, failure, retry, and read-only states use the shared design-system vocabulary and accessible live regions. Persistent context, loading failures, disabled/degraded states, and errors that require correction remain local to their page, form, card, or dialog. Terminal global action feedback uses the design system's single top overlay Toast queue and never enters normal page flow.

- `mode` is not part of the production Feed experience. Legacy `mode` query parameters are removed while preserving `item`.

## 5. Workbench shell and responsiveness

- Expanded navigation is organized as 浏览（信息流、收藏、历史）、常用视图（全部、当天、公共订阅、私人订阅）and 管理（订阅、助手连接、设置、用户管理）. 稍后读、未读、AI、朋友动态、产品机会 are absent. `全部` is the aligned baseline state: it clears unread/source/channel/topic/subscription-scope filters while preserving the user's selected order and sort basis. Other quick views only transform the existing user-isolated Feed preference and introduce no API or URL state. Public scope includes legacy `workspace` catalog rows; private scope contains only the current user's visible private sources.
- Expanded route rows and quick-view rows use one shared sidebar navigation pattern: 40 px minimum height, identical spacing, control typography, focus ring, hover surface, and selected state. Sidebar rows never scale or translate on hover or press; the quick-view dot is the only structural difference.
- The collapsed brand uses the Inteliscope scope mark rather than a text initial. The bottom account Popover opens vertically above its avatar trigger and contains identity, Chinese role, account/member settings, operation manual, Changelog, the external GitHub Release destination, and an explicit logout action. In expanded navigation, the avatar/name trigger is separated from an independent far-right “文档与发布” trigger; its own upward Popover offers operation manual, Changelog, and Release choices instead of navigating immediately. Collapsed/tablet layouts use the account fallback, and mobile Settings exposes the same three destinations. A standalone logout icon is not rendered.
- At 1360 px and above, expanded navigation retains the Inteliscope brand and uses the approved rounded split-panel control to collapse. Collapsed desktop and 768–1359 px overlay triggers use the same 40 px control: closed is neutral with restrained hover/press feedback, and open alone uses the accent surface and text, matching the Agent toggle. Mobile navigation remains unchanged.
- Header height is 52 px. The Web application does not imitate macOS traffic lights, window chrome, drag regions, or desktop-only operating-system controls.
- `/feed`, collection routes, administration pages and authentication all inherit the application font stack and semantic typography scale from the design system. A route must not switch typography independently.
- Every production route uses the shared Quiet Studio page patterns. A route has exactly one page title in `PageHeader`; authenticated headers contain only that title and an action group ordered dark/light mode → applicable Insights → applicable Agent, while count, search, order, filter, and refresh actions live in the aligned `ViewBar` below.
- `PageFrame` owns the three approved content widths: reading pages use approximately 820 px, administration pages approximately 1180 px, and authentication approximately 420 px. Business pages select `reading`, `admin`, or `auth` and may not recreate those widths.
- At 1360 px and above, the user-isolated sidebar may toggle between 72 px and 232 px; the preference key is `inteliscope.ui.sidebar.v1:<user_id>`, accepted values are `collapsed` and `expanded`, and absent or invalid values resolve to collapsed. Accounts never share the preference.
- From 1200–1359 px, navigation remains 72 px. The scope mark opens the categorized 260 px overlay without changing Feed width or scroll; the persisted sidebar-width toggle is not presented.
- From 768–1199 px, navigation remains 72 px and the scope mark opens the same categorized overlay. Agent docking is decided from measured available width rather than from a fixed breakpoint: it docks only when the current sidebar still leaves at least 640 px for Feed, 320 px for Agent and the 10 px separator; otherwise it is an on-demand right Drawer.
- At 767 px and below, content is single-column, navigation moves to a safe-area-aware bottom bar, and Agent is a bottom sheet ending at the viewport bottom. The bar keeps four primary destinations plus `更多与账户`; that Bottom Sheet provides account/member settings, Settings, operation manual, Changelog, Release and an explicit logout action, so every authenticated account has a reachable exit.
- At 1440×900, the workbench shows complete navigation and a centered reading column with four to five complete collapsed cards; Agent normally opens as a 360 px fixed rail. Whenever the measured layout can satisfy the minimum widths, the Agent rail is user-resizable from 320–720 px while preserving a minimum 640 px Feed region, and the clamped width persists only under `inteliscope.ui.right-rail.v1:<user_id>`. A 10 px accessible separator supports pointer drag, arrow keys, Shift acceleration, Home/End and double-click reset. At 1024×768 Agent overlays without resizing or scrolling the Feed. At 390×844, bottom navigation and the selected right-rail sheet remain reachable without horizontal page overflow.
- Navigation, Feed, Agent, Insights, and administration pages use the shared `quiet-scroll-region`: the track is transparent and continuous with its surface, the rounded thumb is subdued at rest and brightens on hover/drag, and horizontal overflow is not introduced. Feed and Agent retain independent vertical scrolling. Fixed Agent state is `closed | agent`; Insights is a separate `closed | auto | manual | closing` floating surface. User-triggered desktop sidebar and fixed Agent-rail changes animate their grid tracks and local content over the 220 ms deliberate-motion token; closing Agent and Insights surfaces remain mounted but inert until their motion finishes. Initial bootstrap restoration, responsive mode switches and pointer resizing settle without replaying that transition. Opening, closing, resizing, or switching preserves route, selected/expanded story, and Feed rendered-ID-plus-offset anchor. Escape closes overlays and restores focus to their trigger.
- The refresh bootstrap snapshot is user-isolated once authentication is known and preserves collapsed/expanded navigation plus the fixed Agent rail's open state and width. The Agent rail is restored only when the measured desktop layout can still dock it; tablet/mobile refresh never opens an overlay Drawer automatically.

## 6. Feed, virtualization, and OpenClaw conversation

- Feed has one mode, 全部. It defaults to `最新优先`, with newest content at the top; the explicit `最新优先`/`最旧优先` control persists per user and applies consistently to `/feed`, `/saved`, and `/history`. A peer `发布时间`/`入库时间` basis control chooses which timestamp determines that ordering. Initial measurement starts at the top for either direction. Changing direction or basis deliberately resets to the top, while an explicit deep-link target remains centered and the current control presentation remains unchanged.
- `/feed` reads the canonical all-items response; `/saved` and `/history` reuse the same card, virtualization, filter, deep-link, and scroll behaviors.
- Long lists are virtualized with stable item IDs. A data reload or background update captures the current rendered item ID and relative viewport offset synchronously at the request boundary. Measurement changes and source replacement retain that anchor; user scrolling cancels restoration ownership.
- New content auto-follows only when the viewport is within 96 px of the active fresh edge: top for newest-first and bottom for oldest-first. Otherwise the position remains stable and an explicit `N 条新内容` action appears at that edge.
- The centered content view bar aligns to the card column. Feed shows item count, order direction, sort basis, a read-only `重新载入` action, a mutating `获取新内容` action, filter, active-filter count, and removable summaries for every active constraint without recreating the removed search control. An icon-only responsive state always has an anchored Tooltip. `重新载入` always re-reads the current user's canonical `/api/feed/latest` snapshot, is available to every role, and never checks Worker state or creates a Job. Its pending state keeps the visible label and control geometry unchanged, disables repeat activation, exposes `aria-busy=true`, and rotates only the existing icon; Reduced Motion removes that rotation. `获取新内容` retains the existing non-viewer Worker workflow. An observed `user_feed_refresh` or `source_fetch` success/partial terminal state must force the latest Feed read before its completion feedback claims that content is ready; a read failure keeps the last trusted cards and directs the user to retry `重新载入`. Completion feedback and run-record headlines use the post-merge adjacent-snapshot `new_item_count`; they never present snapshot `item_count` or source `fetched_count` as the number of additions, and legacy jobs without the additive field omit the numeric claim. Saved and history place count, route-local search, order, and filter in the same bar without either Feed action; mobile search expands from an explicit control. Saved/history search state is isolated by user and route and is never applied invisibly after returning to Feed. Feed filters include unread-first, local-day scope, public/private subscription scope, source, channel, and topic. AI score controls are not rendered and a stale stored minimum-score value is ignored. Preferences remain user-isolated. `当天` follows the browser's local natural day, falls back from published time to fetched time, and recomputes at local midnight, focus, and visibility restoration. Filtering, quick views, unread-first reordering, data reload, and background update preserve rendered-ID anchors; ordering and sort-basis changes use the explicit top reset above.
- Article, RSS, and release cards show source, time, title, an optional distinct summary, channel/topics, optional media, and bounded plain text on expansion. A summary that normalizes to the title or substantially repeats its truncated prefix is omitted rather than repeated or replaced with filler. Collapsed title and distinct summary are each limited to two lines; expansion is inline and does not replace the list or move the viewport anchor.
- Every content card exposes subdued flat format/media metadata before channel/topics: 文章、视频、图片、图集、音频、社交动态、讨论、版本发布或其他. The channel may use one light neutral `MetaTag`; topics render as `#主题` text with a bounded `+N`, rather than putting format, media, channel and every topic into equivalent pills. When images exist, the flat metadata shows the upstream and locally viewable counts, for example `图片 6/8`. Expanded media uses only authenticated local `/api/media/*` URLs and renders at most six images in a stable responsive gallery whose bounded thumbnails use `object-fit: contain`. Each cached image opens one shared, focus-trapped full-image Modal at the selected index; the Modal preserves the original aspect ratio, reports current/total, provides a thumbnail rail, cycles by labelled controls, Arrow keys or touch swipe, prefetches only adjacent authenticated images, and restores focus without changing the selected Feed item or vertical anchor. Loading uses fixed geometry; one broken image reports a local retry without collapsing or failing the card.
- Social cards are source-first. Their metadata line presents platform, followed person/account, source handle, and time with normalized duplicate parts removed. They render exactly one visible content block selected from captured excerpt, captured body, summary, then generated title; collapsed content is limited to three lines and inline expansion replaces it with the available fuller captured body instead of adding a second copy. Legacy social snapshots fall back to platform/catalog type when `content_kind` is absent.
- Expandability and source completeness are separate signals. A card renders icon-only `UnfoldVertical`/`FoldVertical` controls with an `展开内容`/`收起内容` Tooltip and complete `aria-label/aria-expanded/aria-controls` only when measured line-clamp overflow, a distinct detail body, or cached media makes expansion useful; a fully visible short card has no false button or `aria-expanded`. The footer's noninteractive metadata and blank area share the expansion pointer target, while links, buttons, form controls, the explicit expand/collapse trigger, and the direct-action group are excluded so one press never performs two actions. Collapsed detail is inert as well as hidden. `excerpt_only` and capture-stage truncation are explained inside the expanded region and direct the reader to the original source. Detail loading and failure remain local to the selected card.
- Direct actions are open original, save, and the labelled `问 Agent`; after selection it says `已加入 N/8`. Copy summary and dismiss live in one controlled compact overflow menu that closes on Escape, outside press and action completion and restores focus. Read-state controls and AI-score UI are not rendered in the current product. Dismiss moves the item into the account-isolated ignored collection, which is restored from Settings; dismiss and removing a saved item also expose an eight-second Undo Toast that rolls back through the existing endpoint and restores the original list order. There is no read-later action. The complete footer action row—expand/collapse, open original, save, Agent context, and overflow—uses delayed explanatory Tooltips whose real interactive triggers own the positioning reference; these Tooltips prefer directly above the trigger with an 8 px gap and viewport padding, then flip or shift when obstructed instead of falling back to the viewport origin. Tooltip defaults outside card footers remain unchanged. The Agent-context action is neutral and unfilled while idle, becomes a restrained purple selected control with `aria-pressed=true`, and never changes into a check or punctuation glyph.
- Feed, saved and history empty states distinguish first use, an empty collection and an empty filtered result and offer the nearest safe action: subscribe sources, get new content, clear search/filter, or return to Feed. Feed Insights headline counts and channel/format rows are actionable links or filter activators when the corresponding destination exists.
- `/feed`, `/saved`, and `/history` use the same Quiet Studio presentation: no progress rail or reserved rail gutter, a reading-width card column that is centered by default and moves only under the explicit Feed Insights rule below, an 18 px semantic content-card radius, standard graphite surfaces, thin semantic borders, and no persistent glow or heavy shadow.
- Quiet Studio card hover and press feedback uses the existing 120–220 ms motion tokens; inline expansion preserves the rendered ID-plus-offset anchor. Coarse-pointer actions remain fully visible and at least 44 px, and Reduced Motion makes displacement and expansion effectively immediate without hiding state.
- Content-card dimensions and reading width are owned by design-system tokens and presets. Feature code may compose layout, but it may not recreate approved page widths, typography, colors, shadows, radii, or motion values.
- `/feed` exposes peer `信息概览` and `Agent` panel toggles with neutral hover/press feedback and a restrained accent selected state. Insights is one approximately 352 px Quiet Studio grouped card, never a width-owning third column. It may appear automatically once per browser session only when the original measured empty gutter to the right of the centered 820 px reading frame is at least 376 px and Feed data is nonempty; automatic display never moves or covers content and never takes focus. A manual open keeps Insights anchored 12 px inside the current main area's right edge and first translates the aligned ViewBar, card column, loading, empty, and failure reading surfaces left by only the amount needed for a 12 px inter-surface gap, consuming the centered column's left gutter down to a 12 px main-area inset. Only any remaining shortfall may overlap a card. The same geometry is recomputed from the main area when the sidebar, viewport, or resizable fixed Agent rail changes; the 820 px reading width and vertical Feed anchor do not change. The translation uses the 220 ms deliberate-motion token, follows pointer rail resizing without transition, and becomes immediate under Reduced Motion. A manual close suppresses further automatic display in that session, while the toggle can always reopen it as this anchored surface or a mobile Bottom Sheet. On a dock-capable desktop, the floating Insights card and fixed Agent rail may remain visible simultaneously; on overlay and mobile layouts they remain mutually exclusive. If measured Insights geometry still overlaps the Feed reading frame after exhausting the safe left gutter, a primary-pointer press anywhere in the workbench on a target outside Insights with no interactive semantics—including header text, card text, and otherwise inactive canvas—closes only Insights; links, buttons, form controls, editable content, and the Insights surface itself remain usable, and the same press preserves a non-overlapping surface. Closing uses the 220 ms design-system exit, remains mounted, hidden, inert, and pointer-disabled until completion, and becomes effectively immediate under Reduced Motion. Adding context or sending opens Agent, and an active generation pins Agent so the stop control cannot be hidden. The card follows its actual content height, omits empty distribution groups, shows the first three channel/type rows, and grows when the user explicitly chooses `查看更多`; only content exceeding the safe viewport height becomes vertically scrollable. Insights reuses the existing latest Feed, source catalog, source-health, current-account subscription and recent-job queries to show today's content, unread, saved, unhealthy-source, scope-correct visible/total, channel and content-format counts. A separate `订阅与运行` group shows current-account subscription count, the role-matched include-disabled source-catalog count, and only the current user's records from the latest at-most-100 jobs. Those three requests load independently and render `—`, never a false zero, on failure; their actions deep-link to `/subscriptions?tab=subscriptions|library|jobs`. It never introduces a chart library or a new API.
- Agent context contains at most eight ordered safe records per Inteliscope user and browser tab: Feed records use `articleId/title/sourceName?/publishedAt?`, and selected run records additionally carry a safe browser display status while keeping their job ID internal, plus the pending question. Adding either record only updates context and focuses the composer; it never sends a message or incurs model cost. The V5 Gateway handoff has two explicit modes. One or more attached records produce `context_readonly`: the prompt contains the question and internal record IDs, never article body or UI error/detail text, routes Feed records to `get_item` and run records directly to read-only `diagnose_job`, requires persisted evidence and explicit unknowns, and forbids retry, cancellation, repair, or other mutation. A nonempty question with zero attached records produces `direct`: it preserves the user's direct request and may use the controlled subscription flow, but ordinary requests stop after `prepare` and preview; only a later question exactly equal to the current proposal's server-returned confirmation phrase may call `apply_subscription_change`. The prompt must never synthesize, rewrite, or answer that phrase for the user, and neither mode expands the delegation, role, feature-flag, or MCP transaction boundary. Browser-visible projection continues to recognize V4, V3, and legacy handoffs without exposing internal instructions or IDs. Fake `auto/fast/deep` browser preferences are not persisted; connected model and thinking choices come from the active OpenClaw session.
- The connected composer summarizes context as a count plus at most two single-line source/title rows with fixed remove controls; `查看全部` opens a bounded popover containing all eight ordered rows. Long text ellipsizes, raw article IDs never become UI copy, and no context surface scrolls horizontally. In a long connected conversation, only the transcript consumes the remaining height and scrolls; the composer dock never shrinks or leaves the panel viewport. New selections use the card display model immediately; migrated ID-only drafts resolve through the user-scoped `feedItem` query. Loading or unavailable items degrade independently and remain removable.
- With `HORIZON_OPENCLAW_CHAT_ENABLED=false`, desktop sidebar, tablet Drawer, and mobile Bottom Sheet render the existing deterministic copy handoff and create no WebSocket, local-address request, or MCP call. With the flag enabled, the same responsive containers render the browser-to-Gateway conversation: desktop fixed panel, tablet overlay, and mobile bottom/full-height sheet.
- The disabled-mode `HandoffComposer` exposes a compact `交接模式` explanation, context count, transient live status, labelled circular copy action, and the explicit statement that execution uses the destination OpenClaw's current model. It never offers invented model choices. Clipboard failure preserves the draft.
- Browser chat states are `未连接/连接中/已连接/重连中/工具未发现`. A tab owns at most one Gateway WebSocket and one dedicated session key, supports history, streaming, stop, new conversation and reconnect, and bounds visible history to the newest 100 messages and 100,000 text characters. Existing keys reconnect without creating or listing sessions; every new initial, blank, forked, or user-requested conversation uses `Inteliscope · <site host> · <16 hex>`, never contains the Inteliscope user ID, and retries once with a fresh label only on an explicit collision, so test and production origins can share one Gateway without sharing history. Every send creates a stable client turn, synchronously updates React state, the current in-memory reference and the user/Gateway/session-scoped transcript before the Gateway request begins, clears the pending question/context, and sends a separate versioned MCP handoff prompt with a unique idempotency key and `deliver:false`; history projection recognizes both the versioned envelope and legacy handoff prompts without exposing internal instructions or article IDs. Gateway history is incrementally reconciled by message ID, client turn ID and normalized visible message identity and must never replace a local user message merely because Gateway history omitted it. The same fingerprint restores visible user and assistant messages after replies, refresh and ordinary reconnect; model forks migrate the visible transcript. Completed requests never persist the full MCP prompt, while pending/failed requests retain only the bounded retry snapshot. New blank conversation, logout and “忘记此浏览器” clear the applicable session transcript; ordinary disconnect does not.
- Every send inserts a trusted local run activity within the same render turn, before any Gateway delta. When supported, current-session/current-run `agent`, `lifecycle`, `tool` and `thinking` events are sequence/tool-call deduplicated and projected into at most three safe Chinese activity rows; thinking is only `正在思考`, allowlisted tools use product labels, and an unknown tool is `正在使用工具`. Rapid steps are coalesced to avoid flashing. Raw thoughts, tool arguments/results/meta, raw errors, URLs, tokens and confirmation phrases never render or persist. The active trace is one line by default, may expand, and folds after completion into `已完成 N 个步骤 · Ns`; it exists only for the current page session. Without event capability the immediate local row remains. Stopping before the first delta produces `已停止，未生成回答`; stopping later preserves the partial answer and marks it stopped.
- Reconnection feedback lives beside the composer as `连接中断，正在重连 · 第 N 次`, keeps the draft and exposes a retry after terminal failure. A user who has scrolled upward is never forced back to the live edge; an explicit `有新回复 ↓` control appears instead. The textarea grows from 44–120 px. While an IME composition is active, or the native Enter reports `isComposing` or WebKit key code 229, Enter is reserved for candidate confirmation and never prevents default or sends; outside composition, Enter sends once and Shift+Enter inserts a newline. Empty-state suggestions only fill and focus the composer and never send automatically.
- The composer runtime row places a compact circular context-use indicator immediately before the model control. Its hover/focus help contains only current-session used tokens, capacity and percentage. It exact-matches the already stored session key against `sessions.list` and `sessions.changed`, accepts only positive numeric totals whose `totalTokensFresh` is not false, and never adopts another session or estimates missing/stale capacity. Untrusted, stale, malformed, or mismatched data renders a neutral ring labelled `暂无可信用量`; the Agent header does not duplicate model, attachment or context data in a background-information popover.
- Connected model choices come only from `models.list(view=configured)` and the active Agent/session returned by `agents.list` and `sessions.describe`. Bare catalog IDs are normalized to canonical `provider/model` IDs before comparison and before `sessions.create`. The single model menu groups its second-level model entries under first-seen provider headings and preserves Gateway order within each provider. Compact runtime controls separately display exact-session context use, the model verified from `sessions.describe`, and the active thinking level, never optimistic browser values. The model control owns the flexible truncated track, the thinking control remains intrinsically sized, and each opens only its own upward selection menu while the fixed send/stop action remains visible at the 320 px rail minimum. Model switching creates a child session with `sessions.create({parentSessionKey,fork:true,model})`, verifies the returned session model, and only then replaces the locally stored session key; failure archives the unusable branch best-effort and preserves the original conversation. An overlong conversation offers an explicit blank-session fallback instead of silently clearing history. Selectable thinking levels come only from the exact model metadata or the exact current `sessions.describe` result; Agent-level levels never fill a missing model capability. `reasoning=false` or missing verified levels leaves a disabled `自动` control with an explanation. ## 9. Enforcement and acceptance

Every production UI change must pass, in order:

1. Static UI contract checks, product-documentation merge maintenance, and ESLint import restrictions.
2. TypeScript and Vitest.
3. Vite production build and artifact scan proving no MUI/Emotion modules, `Mui` class markers, deleted preview routes, or deleted comparison copy.
4. Playwright at 1440×900, 1024×768, and 390×844, including persisted manual dark/light choices, Reduced Motion, and Axe with zero serious or critical findings.
5. Nearby/collision-aware Tooltip geometry, Reduced Motion, focus restoration, independent scrolling, sidebar/Agent track continuity, stable ID-plus-offset anchors where required, explicit Feed top resets after sort changes, bounded virtualization, and no horizontal overflow checks.

The static contract rejects MUI/Emotion imports, production feature-level direct HeroUI imports, nested `DesignSystemProvider` mounts, raw business-page colors, page-level visual constants, business-owned copies of the approved PageFrame widths, and deleted preview technology. Snapshot or expectation changes require an intentional contract change; they are not an automatic response to a failing visual test.
