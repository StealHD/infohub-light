# Inteliscope UI Contract

## 1. Authority

This file is the sole source of truth for production UI technology, visual language, responsive behavior, and browser acceptance. `PLAN.md` records delivery state, `DECISION_LOG.md` records durable choices, and `tests/test_impact_map.json` selects verification; they must reference this contract rather than restate its visual rules. API fields, authorization, query ownership, and error envelopes remain governed by `API_CONTRACT.md` and existing application tests.

## 2. Production UI system

- Production uses React 19, HeroUI v3, Tailwind CSS v4, Lucide icons, and the self-hosted Noto Sans SC variable font.
- `frontend/src/design-system/**` owns the semantic theme, approved component exports, icon exports, and React Router bridge. Production application and feature code import UI components through this boundary and do not import `@heroui/*` directly.
- `AppBootstrap` mounts exactly one `DesignSystemProvider`, inside `BrowserRouter` and outside production routes. It remains inside the existing `QueryClientProvider`; Query Client, authentication, `ServiceApi`, caches, permissions, and query keys retain their existing lifetimes.
- MUI, MUI Icons, and Emotion are not production dependencies or source technologies. `frontend/src/ui/**`, the MUI prototype, and page-level legacy visual CSS Modules do not exist.
- The sole direct-HeroUI feature exception is the fixed-data development preview at `frontend/src/features/workbench-heroui/**`.

## 3. Visual language

- Production exposes exactly two application color modes: dark and light. Dark is the compatibility default and preserves the current graphite appearance; a shared icon-only control at the top-right of authenticated headers and the login surface changes the browser-persisted choice. The HTML bootstrap sanitizes and restores the same `inteliscope.ui.theme.v1` preference before React starts, so refresh does not flash the other mode and later operating-system appearance changes do not override the explicit choice. Color mode remains separate from the `graphite-purple` theme-family identifier so a future family can be added without changing the two-mode control. Both modes use quiet neutral canvases, layered semantic surfaces, restrained purple accents, semantic separators, and visible accessible focus rings; raw palette values belong only in design-system theme assets.
- The entire production application uses one system UI font stack: `-apple-system`, `BlinkMacSystemFont`, SF Pro where available, `PingFang SC` for Chinese on Apple platforms, then the self-hosted `Noto Sans SC Variable` and system sans-serif fallbacks. Routes and feature components may not define a competing font stack.
- Typography has exactly eleven semantic roles. Their implementation lives in `frontend/src/design-system/theme.css`; business code selects a role and never recreates its size, weight, line height, or letter spacing.

| Role | Size / line | Weight | Intended use |
|---|---:|---:|---|
| `type-display` | 24 / 32 px | 600 | standalone authentication or dedicated display titles |
| `type-section-title` | 18 / 26 px | 600 | major page sections |
| `type-page-title` | 16 / 24 px | 600 | workbench headers, dialogs, card section headers |
| `type-card-title` | 16 / 23 px | 600 | Feed, saved, and history card titles |
| `type-body` | 14 / 22 px | 400 | summaries, descriptions, notices, ordinary content |
| `type-chat` | 13 / 20 px | 400 | compact OpenClaw user and assistant message bodies |
| `type-control` | 13 / 20 px | 500 | buttons, toolbar values, navigation and menu actions |
| `type-meta` | 12 / 18 px | 400 | source, time, counts and technical metadata |
| `type-label` | 11 / 16 px | 500 | navigation group labels and compact composer labels |
| `type-micro` | 10 / 14 px | 500 | count badges and mobile navigation captions |
| `type-prose` | 14 / 26 px | 400 | expanded captured body text |

- Elements in one functional group use the same semantic role. In particular, the Feed view bar count and search use `type-control`, while its icon-only sort, reload, update and filter actions expose complete accessible names plus hover/focus explanations; source and time share `type-meta`; channel/topic metadata uses `type-meta` or `type-micro` according to density.
- Compact semantics are intentionally split instead of being expressed by one global Chip treatment. `StatusIndicator` represents running, connection, health, success, warning and failure with a distinct glyph and tone and never relies on color alone. Its default renders at least 12 px visible text; high-density source health, run records, global schedule and Agent connection/pairing placements may opt into `iconOnly`, which keeps the full accessible name and reveals the same text from an above-anchored Tooltip on hover or keyboard focus. The OpenClaw conversation header retains a compact visible state label. Notices, Toasts, dialogs, run traces and actionable recovery copy retain visible text. `MetaTag` represents channel, topic, format, scope and permission as neutral metadata; `CountBadge` represents only a count; `RemovableTag` is reserved for editable state, is keyboard focusable, has a remove target of at least 28 px and exposes pending/disabled state. Feature code does not globally resize every Chip or use a status pill for ordinary metadata.
- Production business code may not use Tailwind font-size, font-weight, line-height, or letter-spacing utilities (`text-xs`, `text-[…]`, `font-*`, `leading-*`, `tracking-*`). The executable UI contract rejects them. Alignment and semantic color utilities such as `text-left` and `text-muted` remain allowed.
- Radius scale: 16 px panels, 14 px cards, 10 px controls, and 8 px small controls. Static surfaces use contrast and a thin separator rather than glow or heavy shadow.
- Purposeful transitions run for 120–220 ms. Reduced Motion makes nonessential transitions effectively immediate while preserving loading indicators' understandable state.
- A hard refresh paints the graphite background and the last known navigation, header, Feed, and eligible docked Agent geometry directly from the HTML bootstrap shell. React removes that shell only after the authenticated route has committed; the root, shell, and page may not use an opacity entrance or replay a page-level entrance animation during takeover.
- Initial Feed and Agent reads use fixed-geometry design-system Skeletons that preserve the real column widths and closely approximate the loaded block heights. Loading motion is an opacity-only 1,400 ms restrained breath with no traveling shimmer. When data becomes available, only the local data layer transitions: Skeleton opacity exits in 120 ms and content reveals over 200 ms from `translateY(4px)` to rest. Reduced Motion makes all three effects immediate.
- Feature code does not define raw colors, shadows, radii, transition durations, or new page-level CSS visual systems. Native layout values may be used only where the static contract explicitly permits them.
- Loading, empty, degraded, failure, retry, and read-only states use the shared design-system vocabulary and accessible live regions. Persistent context, loading failures, disabled/degraded states, and errors that require correction remain local to their page, form, card, or dialog. Terminal global action feedback uses the design system's single top overlay Toast queue and never enters normal page flow.

## 4. Routes and page ownership

| Route | Production experience |
|---|---|
| `/feed` | Hero workbench, all items |
| `/saved` | Hero workbench, saved collection |
| `/history` | Hero workbench, history collection |
| `/subscriptions` | Quiet Studio adaptive administration page with the same on-demand Agent rail/Drawer as Feed |
| `/agents` | Quiet Studio adaptive assistant-connection page; no Agent panel |
| `/settings` | Quiet Studio adaptive settings page; no Agent panel |
| `/manual` | Quiet Studio source-controlled operation manual with responsive section navigation and no Agent panel |
| `/changelog` | Quiet Studio product changelog with source-controlled Chinese entries, responsive month navigation, and no Agent panel |
| `/login` | Standalone Quiet Studio login page |

- `/later` permanently replaces to `/saved`, preserves only a valid `item` query value, and removes legacy `mode`.
- Authenticated unknown routes resolve coherently to the production Feed; unauthenticated protected routes resolve through the standalone login flow.
- `mode` is not part of the production Feed experience. Legacy `mode` query parameters are removed while preserving `item`.

## 5. Workbench shell and responsiveness

- Expanded navigation is organized as 浏览（信息流、收藏、历史）、常用视图（全部、当天、公共订阅、私人订阅）and 管理（订阅、助手连接、设置、用户管理）. 稍后读、未读、AI、朋友动态、产品机会 are absent. `全部` is the aligned baseline state: it clears unread/source/channel/topic/date/subscription-scope filters while preserving the user's selected order and sort basis, but always remains inside the workspace `feed_window_days`. `当天` uses the server `Asia/Shanghai` natural-day bucket; public scope includes legacy `workspace` catalog rows, and private scope contains only the current user's visible private sources. Other quick views transform the existing user-isolated Feed preference and introduce no API or URL state.
- Expanded route rows and quick-view rows use one shared sidebar navigation pattern: 40 px minimum height, identical spacing, control typography, focus ring, hover surface, and selected state. Sidebar rows never scale or translate on hover or press; the quick-view dot is the only structural difference.
- The collapsed brand uses the Inteliscope scope mark rather than a text initial. The bottom account Popover opens vertically above its avatar trigger and contains identity, Chinese role, account/member settings, operation manual, Changelog, the external GitHub Release destination, and an explicit logout action. In expanded navigation, the avatar/name trigger is separated from an independent far-right “文档与发布” trigger; its own upward Popover offers operation manual, Changelog, and Release choices instead of navigating immediately. Collapsed/tablet layouts use the account fallback, and mobile Settings exposes the same three destinations. A standalone logout icon is not rendered.
- At 1360 px and above, expanded navigation retains the Inteliscope brand and uses the approved rounded split-panel control to collapse. Collapsed desktop and 768–1359 px overlay triggers use the same 40 px control: closed is neutral with restrained hover/press feedback, and open alone uses the accent surface and text, matching the Agent toggle. Mobile navigation remains unchanged.
- Header height is 52 px. The Web application does not imitate macOS traffic lights, window chrome, drag regions, or desktop-only operating-system controls.
- `/feed`, collection routes, administration pages and authentication all inherit the application font stack and semantic typography scale from the design system. A route must not switch typography independently.
- Every production route uses the shared Quiet Studio page patterns. A route has exactly one page title in `PageHeader`; authenticated headers contain only that title and an action group ordered dark/light mode → applicable Insights → applicable Agent, while count, search, order, filter, and refresh actions live in the aligned `ViewBar` below.
- `PageFrame` owns the three approved content widths: reading pages use approximately 820 px, administration pages approximately 1180 px, and authentication approximately 420 px. Business pages select `reading`, `admin`, or `auth` and may not recreate those widths.
- At 1360 px and above, the user-isolated sidebar may toggle between 72 px and 232 px; the preference key is `inteliscope.ui.sidebar.v1:<user_id>`, accepted values are `collapsed` and `expanded`, and absent or invalid values resolve to collapsed. Accounts never share the preference.
- From 1200–1359 px, navigation remains 72 px. The scope mark opens the categorized 260 px overlay without changing Feed width or scroll; the persisted sidebar-width toggle is not presented.
- From 768–1199 px, navigation remains 72 px and the scope mark opens the same categorized overlay. Agent docking is decided from measured available width rather than from a fixed breakpoint: it docks only when the current sidebar still leaves at least 640 px for Feed, 320 px for Agent and the 10 px separator; otherwise it is an on-demand right Drawer.
- At 767 px and below, content is single-column, navigation moves to a safe-area-aware bottom bar, and Agent is a bottom sheet ending at the viewport bottom. The bar keeps four primary destinations plus `更多与账户`; that Bottom Sheet provides account/member settings, Settings, operation manual, Changelog, Release and an explicit logout action, so every authenticated account has a reachable exit.
- At 1440×900, the workbench shows complete navigation and a centered reading column with four to five complete collapsed cards; Agent normally opens as a 400 px fixed rail. Whenever the measured layout can satisfy the minimum widths, the Agent rail is user-resizable from 320–720 px while preserving a minimum 640 px Feed region, and the clamped width persists only under `inteliscope.ui.right-rail.v1:<user_id>`. A 10 px accessible separator supports pointer drag, arrow keys, Shift acceleration, Home/End and double-click reset. At 1024×768 Agent overlays without resizing or scrolling the Feed. At 390×844, bottom navigation and the selected right-rail sheet remain reachable without horizontal page overflow.
- Navigation, Feed, Agent, Insights, and administration pages use the shared `quiet-scroll-region`: the track is transparent and continuous with its surface, the rounded thumb is subdued at rest and brightens on hover/drag, and horizontal overflow is not introduced. Feed and Agent retain independent vertical scrolling. Fixed Agent state is `closed | agent`; Insights is a separate `closed | auto | manual | closing` floating surface. User-triggered desktop sidebar and fixed Agent-rail changes animate their grid tracks and local content over the 220 ms deliberate-motion token; closing Agent and Insights surfaces remain mounted but inert until their motion finishes. Initial bootstrap restoration, responsive mode switches and pointer resizing settle without replaying that transition. Opening, closing, resizing, or switching preserves route, selected/expanded story, and Feed rendered-ID-plus-offset anchor. Escape closes overlays and restores focus to their trigger.
- The refresh bootstrap snapshot is user-isolated once authentication is known and preserves collapsed/expanded navigation plus the fixed Agent rail's open state and width. The Agent rail is restored only when the measured desktop layout can still dock it; tablet/mobile refresh never opens an overlay Drawer automatically.

## 6. Feed, virtualization, and OpenClaw conversation

- Every new or changed production UI starts from HeroUI OSS component anatomy, accessibility, and interaction behavior; HeroUI Pro Default design-system pages are a visual-hierarchy reference only. The local Inteliscope design system and its semantic tokens take precedence, and product code neither imports nor copies HeroUI Pro code or dependencies.
- Feed has one mode, 全部, and its ViewBar always names the active range as `近N天 · N条`; N follows the workspace-wide 7/14/30-day setting. It defaults to `最新优先`, with newest content at the top; the explicit `最新优先`/`最旧优先` control persists per user and applies consistently to ordinary `/feed`, `/saved`, and `/history`. A peer `发布时间`/`入库时间` basis control chooses which timestamp determines that ordering. Initial measurement starts at the top for either direction. Changing direction or basis deliberately resets to the top, while an explicit deep-link target remains centered and the current control presentation remains unchanged.
- `/feed` reads the canonical stable-index projection for the current window; `/saved` and `/history` reuse the same card, virtualization, filter, deep-link, and scroll behaviors. `/saved` reads 50 rows per request as an infinite query and uses the server `item_count` to determine whether another page exists. `/history` reads only content before the current window in explicit server pages, supports `?source_id=<id>&q=<text>`, merges pages by stable item ID and provides a labelled manual `加载更多` action without treating appended historical rows as newly arrived Feed content. Feed global Search also keeps explicit 50-row `加载更多`; a loaded page whose client filters remove every card is not an empty terminal state while another server page exists. Feed, History, global Search and Source Health invalidate together at the next Shanghai midnight computed from the server window.
- A nonempty list renders a terminal sentinel only after its real final page is known. The sentinel is one centered `type-meta` line shaped visually as `· random sentence`; it has no card surface, border, radius, shadow, visible route title, title/body hierarchy, or reserved panel height. The fixed route-aware label—信息流、收藏、历史或搜索结果已全部显示—remains screen-reader-only, while the random sentence comes from the shared `first_end` or `repeat_end` pool. Before the sentinel is actually reached it may show only the lightweight dot and must not expose a live status; the message becomes polite status content only after selection. The first/repeat counter is scoped to the signed-in user and current browser tab, survives refresh through `sessionStorage`, and resets when that user logs out or the tab closes. The sentence remains stable while the sentinel stays visible; leaving it and entering again chooses another sentence without immediate repetition. A short list whose sentinel is already visible counts as a real terminal reach. Loading, errors, an unsubmitted single-character search, and any state with an unloaded page never render the sentinel.
- Long lists are virtualized with stable item IDs. A data reload or background update captures the current rendered item ID and relative viewport offset synchronously at the request boundary. Measurement changes and source replacement retain that anchor; user scrolling cancels restoration ownership.
- New content auto-follows only when the viewport is within 96 px of the active fresh edge: top for newest-first and bottom for oldest-first. Otherwise the position remains stable and an explicit `N 条新内容` action appears at that edge.
- The centered content view bar aligns to the card column. Feed shows its `近N天` count and a global-content search, followed by icon-only order direction, sort basis, read-only `重新载入`, mutating `获取新内容`, and filter actions; active constraints remain removable summaries below. Every icon action has a complete accessible name and a hover/focus explanation without relying on the glyph alone. Search, sort, reload and update explanations use the shared downward-anchored Tooltip preset: they prefer directly below the trigger with an 8 px gap and viewport padding, then flip or shift only when collision handling requires it. The filter remains a downward-opening Popover. This preset is limited to the Feed/Saved/History ViewBar and does not alter card, sidebar or status Tooltips. On mobile, search expands from an explicit icon control. `重新载入` always re-reads the current user's canonical `/api/feed/latest` projection, is available to every role, and never checks Worker state or creates a Job. Its pending state keeps the control geometry unchanged, disables repeat activation, exposes `aria-busy=true`, and rotates only the existing icon; Reduced Motion removes that rotation. `获取新内容` retains the existing non-viewer Worker workflow. An observed `user_feed_refresh` or `source_fetch` success/partial terminal state must force the latest Feed read before its completion feedback claims that content is ready; a read failure keeps the last trusted cards and directs the user to retry `重新载入`. Completion feedback and run-record headlines use the post-merge adjacent-snapshot `new_item_count`; they never present snapshot `item_count` or source `fetched_count` as the number of additions, and legacy jobs without the additive field omit the numeric claim. Saved and history place count, route-local search, order, and filter in the same bar without either Feed action. History shows server `total_count`, reads `q` from its URL, debounces the server query, and represents `source_id` as a removable source-name tag; clearing it preserves unrelated deep-link state. A load-more failure stays local and preserves loaded cards. Feed search enters an explicit `全部内容搜索 · N条` state over Feed, online history and cold metadata; it debounces by 300 ms, cancels stale requests, fixes result order to newest-first, labels each card `今天 / 近N天 / 历史`, requires explicit Enter for a single character and paginates in 50-row pages. Clearing search restores ordinary Feed, filters and reading anchor; search never moves old content into Feed. Feed, saved and history search state is isolated by user and route and never leaks invisibly between routes. Ordinary Feed filters include unread-first, server-day scope, public/private subscription scope, source, channel, and topic; global-search mode temporarily suspends those Feed-only filters and sort controls. AI score controls are not rendered and a stale stored minimum-score value is ignored. Preferences remain user-isolated. `当天` consumes `timeline_bucket=today` from the server, with a browser-local published/fetched fallback only for legacy items lacking that field. Filtering, quick views, unread-first reordering, data reload, and background update preserve rendered-ID anchors; ordering and sort-basis changes use the explicit top reset above.
- Article, RSS, and release cards show a 25 px source avatar before source/time, then title, an optional distinct summary, channel/topics, optional compact media while collapsed, and bounded plain text on expansion. The avatar renders only the current authenticated `/api/media/*` source asset; while missing or broken it keeps the same geometry and shows a platform mark or source initials. A summary that normalizes to the title or substantially repeats its truncated prefix is omitted rather than repeated or replaced with filler. Collapsed title and distinct summary are each limited to two lines; expansion is inline and does not replace the list or move the viewport anchor.
- Every content card exposes subdued flat format/media metadata before channel/topics: 文章、视频、图片、图集、音频、社交动态、讨论、版本发布或其他. The channel may use one light neutral `MetaTag`; topics render as `#主题` text with a bounded `+N`, rather than putting format, media, channel and every topic into equivalent pills. When images exist, the flat metadata shows the upstream and locally viewable counts, for example `图片 6/8`. A collapsed card with locally viewable media shows the first authenticated `/api/media/*` image beside its summary in a fixed 4:3 `contain` stage whose width clamps from 72–88 px. One original image has no decorative back plate, two have one, and three or more have two; the plates use only semantic surfaces and 3/6 px contained offsets, never request another image, rotate, autoplay, or add carousel controls. The compact trigger opens the shared preview at the first viewable index without expanding the card. Expansion replaces rather than duplicates it with the responsive 4:3 representative stage capped at 512×384; cards without locally viewable media keep their existing structure and dimensions. The shared focus-trapped Modal keeps additional images out of the card, and its bounded main-image stage and thumbnail rail occupy separate rows. The main image fills the stage with `width/height: 100%` plus `object-fit: contain`, so portrait and landscape assets remain wholly inside the Dialog and viewport. Multi-image previews report current/total, cycle by labelled controls, thumbnails, Arrow keys or touch swipe, and prefetch only adjacent authenticated images; single-image previews omit navigation controls and the thumbnail rail. Closing restores focus without changing expansion, the selected Feed item, or the vertical anchor. Loading uses fixed geometry; one broken image reports a local retry without collapsing or failing the card.
- Social cards are source-first. Their metadata line presents platform, followed person/account, source handle, and time with normalized duplicate parts removed. They render exactly one visible content block selected from captured excerpt, captured body, summary, then generated title; collapsed content is limited to three lines and inline expansion replaces it with the available fuller captured body instead of adding a second copy. Legacy social snapshots fall back to platform/catalog type when `content_kind` is absent.
- Expandability and source completeness are separate signals. A card renders icon-only `UnfoldVertical`/`FoldVertical` controls with an `展开内容`/`收起内容` Tooltip and complete `aria-label/aria-expanded/aria-controls` only when measured line-clamp overflow, a distinct detail body, or cached media makes expansion useful; a fully visible short card has no false button or `aria-expanded`. The footer's noninteractive metadata and blank area share the expansion pointer target, while links, buttons, form controls, the explicit expand/collapse trigger, the compact media trigger, and the direct-action group are excluded so one press never performs two actions. Collapsed detail is inert as well as hidden; the compact media trigger is its independently focusable sibling outside that inert region. `excerpt_only` and capture-stage truncation are explained inside the expanded region and direct the reader to the original source. Detail loading and failure remain local to the selected card.
- Direct actions are open original, save, and the labelled `问 Agent`; after selection it says `已加入 N/8`. Copy summary and dismiss live in one controlled compact overflow menu that closes on Escape, outside press and action completion and restores focus. Read-state controls and AI-score UI are not rendered in the current product. Dismiss moves the item into the account-isolated ignored collection, which is restored from Settings; dismiss and removing a saved item also expose an eight-second Undo Toast that rolls back through the existing endpoint and restores the original list order. There is no read-later action. The complete footer action row—expand/collapse, open original, save, Agent context, and overflow—uses delayed explanatory Tooltips whose real interactive triggers own the positioning reference; these Tooltips prefer directly above the trigger with an 8 px gap and viewport padding, then flip or shift when obstructed instead of falling back to the viewport origin. Tooltip defaults outside card footers remain unchanged. The Agent-context action is neutral and unfilled while idle, becomes a restrained purple selected control with `aria-pressed=true`, and never changes into a check or punctuation glyph.
- A confirmed final empty Feed, saved, history, filtered, or search result replaces the former empty-state card, title, explanation, and action buttons with the same unframed visual `· random sentence` line from the shared `empty` pool; the route-specific empty meaning remains screen-reader-only and two competing empty messages must never render together. An unsubmitted single-character search is not a final empty result and uses one lightweight `· 输入单个字符后按回车搜索` line instead of either the random empty copy or the old card. Loading, error, or a zero-card client-filtered page with more server pages renders neither the empty sentence nor a false terminal claim. Feed Insights headline counts and channel/format rows remain actionable links or filter activators when the corresponding destination exists.
- `/feed`, `/saved`, and `/history` use the same Quiet Studio presentation: no progress rail or reserved rail gutter, a reading-width card column that is centered by default and moves only under the explicit Feed Insights rule below, an 18 px semantic content-card radius, standard graphite surfaces, thin semantic borders, and no persistent glow or heavy shadow.
- Quiet Studio card hover and press feedback uses the existing 120–220 ms motion tokens; inline expansion preserves the rendered ID-plus-offset anchor. Coarse-pointer actions remain fully visible and at least 44 px, and Reduced Motion makes displacement and expansion effectively immediate without hiding state.
- Content-card dimensions and reading width are owned by design-system tokens and presets. Feature code may compose layout, but it may not recreate approved page widths, typography, colors, shadows, radii, or motion values.
- `/feed` exposes peer `信息概览` and `Agent` panel toggles with neutral hover/press feedback and a restrained accent selected state. Insights is one approximately 352 px Quiet Studio grouped card, never a width-owning third column. It may appear automatically once per browser session only when the original measured empty gutter to the right of the centered 820 px reading frame is at least 376 px and Feed data is nonempty; automatic display never moves or covers content and never takes focus. A manual open keeps Insights anchored 12 px inside the current main area's right edge and first translates the aligned ViewBar, card column, loading, empty, and failure reading surfaces left by only the amount needed for a 12 px inter-surface gap, consuming the centered column's left gutter down to a 12 px main-area inset. Only any remaining shortfall may overlap a card. The same geometry is recomputed from the main area when the sidebar, viewport, or resizable fixed Agent rail changes; the 820 px reading width and vertical Feed anchor do not change. The translation uses the 220 ms deliberate-motion token, follows pointer rail resizing without transition, and becomes immediate under Reduced Motion. A manual close suppresses further automatic display in that session, while the toggle can always reopen it as this anchored surface or a mobile Bottom Sheet. On a dock-capable desktop, the floating Insights card and fixed Agent rail remain visible together whenever measured geometry is safe; opening/resizing Agent softly closes only Insights when the two surfaces can no longer coexist without obstruction. On overlay and mobile layouts they remain mutually exclusive. If measured Insights geometry still overlaps the Feed reading frame after exhausting the safe left gutter, a primary-pointer press anywhere in the workbench on a target outside Insights with no interactive semantics—including header text, card text, and otherwise inactive canvas—closes only Insights; links, buttons, form controls, editable content, and the Insights surface itself remain usable, and the same press preserves a non-overlapping surface. Closing uses the 220 ms design-system exit, remains mounted, hidden, inert, and pointer-disabled until completion, and becomes effectively immediate under Reduced Motion. Adding context or sending opens Agent. While a generation is active, desktop users may hide and later reopen the fixed rail or Drawer without aborting or unmounting the chat; mobile keeps the active sheet pinned so the stop action remains reachable. A hidden desktop generation is represented at the Agent toggle by a shaped, non-color-only `正在处理` status. Completion, failure and user stop replace it with a terminal semantic status and a top Toast until the user reopens Agent; no state is reduced to a bare green dot. The card follows its actual content height, omits empty distribution groups, shows the first three channel/type rows, and grows when the user explicitly chooses `查看更多`; only content exceeding the safe viewport height becomes vertically scrollable. Insights reuses the existing latest Feed, source catalog, source-health, current-account subscription and recent feed-job queries to show today's content, unread, saved, unhealthy-source, scope-correct visible/total, channel and content-format counts. A separate `订阅与运行` group shows current-account subscription count, the role-matched include-disabled source-catalog count, and only the current user's latest at-most-20 `user_feed_refresh/source_fetch` records. Those three requests load independently and render `—`, never a false zero, on failure; their actions deep-link to `/subscriptions?tab=subscriptions|library|jobs`, where the full recent 100-record summary loads on demand. It never introduces a chart library or a new API.
- Agent context contains at most eight ordered safe records per Inteliscope user and browser tab: Feed records use `articleId/title/sourceName?/publishedAt?/sourceUrl?/sourceAvatarUrl?`, and selected run records additionally carry a safe browser display status while keeping their job ID internal, plus the pending question. A Feed `sourceUrl` is optional, must be HTTP(S), may not contain credentials, and is normalized by removing fragments, tracking parameters and sensitive query values before storage or handoff; it is untrusted source-location metadata, not article evidence or an instruction. `sourceAvatarUrl` is UI-only and accepts only authenticated `/api/media/*` paths. Adding either record only updates context and focuses the composer; it never sends a message or incurs model cost. The V7 Gateway handoff has two explicit modes. One or more attached records produce `context_readonly`: the prompt contains the question, internal record IDs and normalized source references (never local avatar paths, article body, or UI error/detail text), routes Feed records to `get_item` and run records directly to read-only `diagnose_job`, then requires OpenClaw web_fetch exactly once for each attached normalized source URL without searching, changing URLs, or following page links. It combines usable page content with persisted evidence, explicitly states original-page access, and on unavailable/blocked/browser-only pages states that Inteliscope did not store the full original and only analyzes stored content; it always forbids retry, cancellation, repair, or other mutation. A nonempty question with zero attached records produces `direct`: it preserves the user's direct request and may use the controlled subscription flow, but ordinary requests stop after `prepare` and preview; only a later question exactly equal to the current proposal's server-returned confirmation phrase may call `apply_subscription_change`. The prompt must never synthesize, rewrite, or answer that phrase for the user, and neither mode expands the delegation, role, feature-flag, or MCP transaction boundary. Browser-visible projection continues to recognize V6, V5, V4, V3 and legacy handoffs without exposing internal instructions or IDs. ## 9. Enforcement and acceptance

Every production UI change must pass, in order:

1. Static UI contract checks, product-documentation merge maintenance, and ESLint import restrictions.
2. TypeScript and Vitest.
3. Vite production build and artifact scan proving no MUI/Emotion modules, `Mui` class markers, deleted preview routes, or deleted comparison copy.
4. Playwright at 1440×900, 1024×768, and 390×844, including persisted manual dark/light choices, Reduced Motion, and Axe with zero serious or critical findings.
5. Nearby/collision-aware Tooltip geometry, Reduced Motion, focus restoration, independent scrolling, sidebar/Agent track continuity, stable ID-plus-offset anchors where required, explicit Feed top resets after sort changes, bounded virtualization, and no horizontal overflow checks.

The static contract rejects MUI/Emotion imports, production feature-level direct HeroUI imports, nested `DesignSystemProvider` mounts, raw business-page colors, page-level visual constants, business-owned copies of the approved PageFrame widths, and deleted preview technology. Snapshot or expectation changes require an intentional contract change; they are not an automatic response to a failing visual test.
