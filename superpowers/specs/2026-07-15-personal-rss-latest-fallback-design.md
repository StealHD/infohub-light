# 个人动态 RSS 最新一条回填设计

日期：2026-07-15

## 目标

为 B 站 UP 主这类个人动态 RSS 增加显式的“保留来源最新一条”能力：抓取窗口内有内容时返回全部窗口内条目；窗口内没有内容时，从该 RSS 中回填发布时间最新的一条。普通新闻 RSS 默认行为不变。

同时修正运行记录的计数语义，不再把最终 Feed 总数标成“新内容”。

## 已确认的用户语义

- 该能力只对显式开启的个人动态 RSS 生效，不根据 URL 自动猜测 B 站路由。
- 窗口内有多条更新时全部显示，不只保留其中一条。
- 窗口内为空时，只回填整个 RSS 中发布时间最新的一条。
- 最新一条可超过全局时间窗口，并且在后续全量刷新中持续保留，直到同来源出现更新的条目。
- HTTP 失败、空 Feed 或所有条目都没有可解析时间时，不伪造回填内容。

## 配置契约

`RSSSourceConfig` 和 RSS catalog source 增加非密密布尔字段：

```json
{
  "keep_latest_item": true
}
```

规则：

- 默认为 `false`，因此现有 RSS 来源无需迁移且行为不变。
- Source Type Registry 将它作为可选布尔字段暴露，帮助文案明确说明“窗口无更新时回填并持续保留最新一条”。
- 本地现有“超Carry的柴西”来源在部署后显式更新为 `keep_latest_item=true`。
- 该字段参与现有共享抓取配置指纹；开启后会自然避开之前缓存的空快照。

## RSS 抓取与保留流程

1. RSS 请求和安全网络策略保持不变。
2. 抓取器先解析所有拥有有效发布时间的条目，再按 `since` 过滤。
3. 如果窗口内有条目，返回全部窗口内条目。
4. 如果窗口内没有条目且 `keep_latest_item=true`，使用 `published_at` 最大的条目作为唯一回填。
5. 在本次选中的条目里，只有发布时间最新的一条获得 `retention_policy=latest_per_source`；其余条目保持 `time_window`。
6. Feed 投影层只接受白名单内的 `latest_per_source|time_window` 策略，并复用现有“同来源最新条目原子替换”合并逻辑。
7. 后续更新出现时，新的最新条目替换旧的长期保留条目；同窗口内的其余条目按现有时间窗口自然过期。

## 任务结果与界面文案

`source_fetch` 结果保留兼容字段 `item_count`，其语义仍是最终用户 Feed 总条数；新增：

```json
{
  "fetched_count": 1,
  "item_count": 4,
  "snapshot_created": true
}
```

- `fetched_count` 来自目标来源的 `SourceOutcome.fetched_count`，表示本次从来源返回的条目数，不声称它们全是新内容。
- `snapshot_created=true` 表示本次确实产生了新的 Feed 快照；`false` 表示信息流无变化。
- 运行记录显示“本次抓取 N 条，信息流已更新”或“本次抓取 N 条，信息流无变化”，不再使用“N 条新内容”。
- 旧 job 没有 `fetched_count` 时，界面只根据 `snapshot_created` 显示“信息流已更新/无变化”，不使用 `item_count` 猜测新增数。

## 失败与边界语义

- HTTP 4xx/5xx、连接超时和解析异常仍走现有来源失败、重试和健康状态逻辑；不将上游失败误报为“没有新内容”。
- 请求成功但 Feed 为空时返回 0 条，不伪造占位内容。
- 没有可解析时间的条目继续被排除，因为无法证明它是最新一条。
- 重复抓到同一条最新内容时，稳定 article ID 和现有快照 hash 保证 `snapshot_created=false`，不产生重复 Feed 条目。
- 已有最新条目时遇到上游失败，现有 partial/失败来源保留逻辑继续保留旧条目，但任务本身仍准确标记失败。

## 测试策略

- RSS 单元测试：默认来源仍严格按时间窗口过滤。
- RSS 单元测试：开启时窗口为空则只返回时间最新的一条，不依赖 RSS 原始排序。
- RSS 单元测试：窗口内多条时全部返回，且只有其中最新一条获得长期保留策略。
- Registry/配置测试：布尔字段默认值、校验、Worker payload 和界面字段定义一致。
- Feed 合并测试：最新一条超过全局窗口后仍保留，新条目到来时原子替换。
- Runner 测试：`fetched_count`、`item_count` 和 `snapshot_created` 的语义分离。
- React 测试：新旧 job 都不再把 Feed 总数标成“新内容”。
- 本地端到端验收：为“超Carry的柴西”开启开关，执行一次单源抓取，验证 2026-07-09 的最新视频进入 Feed，再次抓取不产生重复快照。

## 验收标准

- 未开启开关的 RSS 在窗口内无条目时仍返回 0 条。
- 已开启开关的 RSS 在窗口内无条目时只返回最新一条。
- 已开启开关的 RSS 在窗口内有多条时不丢失任何一条。
- 只有同来源的最新条目超过时间窗口后持续保留，旧的保留条目在新条目到来后被替换。
- 运行记录不再出现把最终 Feed 总数表述为“N 条新内容”的情况。
- 当前 B 站订阅能显示最新一条视频，后续每 6 小时调度保持启用。
- 相关 Python/React 回归、完整 test gate、前端 build、Compose 健康和宿主机/容器代码一致性验证通过。

## 非目标

- 不为所有 RSS 默认开启最新一条回填。
- 不通过 RSSHub 域名或 B 站路由字符串自动识别来源类型。
- 不改变全局 `time_window_hours=24` 的默认值。
- 不回填多条历史内容，不引入按天数的历史重放配置。
- 不解决第三方 RSSHub 实例的可用性问题，也不在本期部署自建 RSSHub。
