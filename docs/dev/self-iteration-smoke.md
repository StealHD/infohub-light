# Inscope 自我迭代首轮演练说明

本演练以源码基线 `0ca5b3b790d1e641483bed2b748e49940bba1bc0` 为起点，由人工控制端在独立任务分支 `iterate/smoke-001` 操作，目标集成分支为 `iterate/inscope`。这是首轮受控文档演练，不表示 Multica 已具备自动派发、自动合并或自动发布能力。

1. 控制端从基线建立独立任务检出，记录任务分支、目标分支、worktree 路径及是否推送；在任何合并前再次公开这四项映射。产物为任务范围和基线记录。若分支、基线或 worktree 身份不一致，立即停止，不以近似提交替代。
2. 完成文档改动后，控制端先审查改动并完成提交前门禁，再提交候选并取得候选的完整 SHA，不得只记录短 SHA，也不得把工作区状态当作候选。产物为候选完整 SHA、`git diff` 审查范围和干净性证据。若存在未解释改动、候选 SHA 不可复现或 diff 超出任务，停止并回到修订。
3. 控制端依项目 `test-gate` 选择文档-only 的 control 门禁，执行适用的结构、Markdown、控制面和 WORKLOG 流程；实际 WORKLOG 由根控制端按规范 append/finalize，不由开发端伪造。产物为门禁命令、退出状态和对应候选 SHA 的摘要。任一门禁失败、证据指向其他 checkout，或最终改动发生在门禁之后，均停止并重新核验。
4. 候选交由独立审查者检查分支目标、完整 SHA、文档事实、失败边界和不夸大表述。产物为独立审查结论及问题清单。发现高置信错误、遗漏停止条件或将能力写成已部署时，停止；修订后须对新 SHA 重做相关门禁和审查。
5. 仅在审查通过的固定候选 SHA 上，由获授权的专用构建端构建候选镜像并锁定 revision、平台和摘要。产物为镜像身份记录；镜像不得含真实 `.env`、数据库、运行凭据、日志或备份。构建来源不是该完整 SHA、摘要无法核对或构建环境污染时，停止。本轮使用登记的上海专用构建端并遵守原资源限额；禁止在东京生产机编译。
6. 控制端使用独立临时运行目录和临时数据库启动该固定镜像，在断网条件下做有限 API 验证，只验证存活、就绪及版本/revision 等不依赖外部服务的接口。产物为临时目录标识、隔离证明和 API 结果。不得使用默认 `up-latest.sh` 触碰已有运行数据，不得以临时库覆盖现有测试库；外部网络可达、数据目录混用、健康失败或 revision 不符都停止并清理临时环境。
7. 全部证据齐备后，控制端创建指向 `iterate/inscope` 的 PR，由人工决定审查与合并。产物为 PR 链接、源/目标分支和候选完整 SHA。PR 目标错误、候选变化或必需审查未完成时停止；本演练不自动合并、更不发布。
8. 本人仅通过 IM 回执确认“候选、门禁、审查、镜像和断网验证证据已提交控制端”。产物为回执文本和时间；IM 当前不保存部署权限，也不授予真实发布权限。没有完整证据时不得发送成功回执。

开发端不持有 Docker、Git 写入凭据或部署密钥，不能提交、推送、构建生产镜像、操作服务器或发布；控制端以独立权限完成交接。任何凭据、私有地址和生产部署命令均不写入本说明。演练记录只能陈述实际已取得的证据，未执行的门禁、验证、PR、通知或发布必须明确为待控制端执行，不能臆造成功结果。
