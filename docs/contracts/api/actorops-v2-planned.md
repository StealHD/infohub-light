# ActorOps v2 计划合同

## 三阶段高适配合同（2026-08-29）

ActorOps 将候选闭环固定为“高质量候选获取 → 系统可用性判断 → 稳定投入使用”。Discovery 合并 Route 能力词后按公开使用人数、评分、评价数、收藏数、活跃度、价格和 exact Build 可用性排序，每个 Route 去重后只分析前五个相关 Candidate；评论、字幕、关系和纯资料 Actor 返回 `wrong_actor_type`，不进入该 Route 的可用性或故障统计。静态 Schema 证明只产生 `static_ready|sample_required`，只有当前 exact Build/Schema、所有现役 Binding 的真实 Dataset 证明和最终费用事实齐备时才投影 `system_usable`。

商城召回最多合并八十条结果，并按质量顺序免费检查最多二十个 exact Revision，直到保留五个 Route 相关 Candidate；错类型、Build/价格/输入预检阻断都不占五个名额。缺失公开 Output Schema 不再淘汰：global 35 `actorops_v2_sampling_plans` 的私有 sidecar 只保存 exact Candidate、Build/Input Schema hash 和经静态证明的 `InputPlan v1`，公共 Candidate 仅投影 `sample_required`、`probe_eligible=true` 与 `output_sample_required`。已有库只能在 API/Worker 停止后显式运行 `scripts/migrate_actorops_v2_sampling.py`，以 `0600` backup、事务安装、shape/integrity/foreign-key 检查完成；迁移不联网、不调用 AI/Actor、不读取 Dataset 或改写费用。

`system_usable=true` 是第二阶段唯一成功语义，并要求 immutable observed Manifest、exact identity 未漂移、当前每个 ready Binding 的 target-bound `valid_nonempty` proof、全部相关费用最终结算、Candidate 非故障且不在冷却。`static_ready` 只表示“可实测”，`sample_required` 只表示输入已证明且等待一次样本；两者均不得进入正式主备或在 UI 显示为可替换。一次管理员按钮授权覆盖一个收费 Run、费用对账和同一 Dataset 最多两轮零新增 Run 的字段修正，最终应用仍需独立按钮确认；浏览器继续在受控请求中发送既有固定确认 token，用户无需手工输入短语，服务端费用门和 CAS 不变。

Manifest v1 可选 `row_extraction`。`top_level` 保持平铺行；`nested_array` 最多六个 JSON Pointer、深度八、两个数组通配层和四条安全筛选，并将子项、直接父对象和顶层上下文投影为只读 `item|parent|root` envelope。筛选值只能来自 exact Schema 的 enum/const 或真实 Dataset 脱敏结构中的安全短枚举。统一展开器最多读取四个顶层 Dataset 行、检查一百个发布型子项；溢出、无法分类的发布型记录或任一跨目标内容均失败关闭。Runtime、Maintenance Probe、Replacement Probe 和 Dataset 重验必须复用该展开与 Adapter 验证入口，不得维护独立解释器。

已授权 Probe 首次因安全映射失败且费用已最终结算、Dataset ID 已与当前 Run 精确绑定时，Replacement 在原 plan 内自动复用同一 Dataset：先生成不含值的结构树，再执行确定性映射和最多两轮 Actor 专用 AI 修正，每轮都通过 exact 输入、虚拟输出 Schema、展开计划、身份/URL/时间/内容合同和全部当前 Binding 的真实行验证。成功创建 immutable successor Candidate、为每条 Binding 写入 `$0`/无 remote Run 的 revalidation evidence，并以 generation CAS 将原计划切换至后继 Candidate；原 Candidate 仅标记映射版本已替代，不标记 Actor 故障。全过程新增 Apify Run 必须为零。两轮仍未证明时，计划必须原子转为 `failed` 并保留具体安全原因、Dataset、Attempt 和费用事实；Candidate 不记故障，Route 立即允许重新选择候选，不得以 `running/adaptation_pending` 永久占用唯一计划。

Candidate 公共投影新增 `compatibility_stage=candidate|static_ready|sample_required|adapting|system_usable|blocked`、`mapping_evidence=schema|dataset` 与 `dataset_shape=flat|nested|mixed|run_bound|unknown`。安全 `mapping_issue_code` 可增加 `nested_extraction_failed|mixed_rows_unclassified|dataset_run_unbound|dataset_expansion_overflow|observed_mapping_failed`。Replacement detail 增加 `phase=schema_analysis|sample_required|dataset_read|dataset_adapting|dataset_revalidating|cost_reconciliation|proof_complete`。这些投影不得返回原始 Dataset、Schema、Manifest、Pointer、目标、账号、模型原文或远端标识。命名 Dataset 只允许读取本次 Run 已登记并写入原 Attempt 的 exact Dataset ID；无法绑定时保持 `dataset_run_unbound`，不得按名称猜测或读取历史共享 Dataset。

Route list/detail 的公共投影包含一个脱敏 `workflow` 摘要：`discovery` 只返回既有安全状态、stage 和有界计数，`replacement` 只返回 plan/槽位/status/phase、来源完成数量、Attempt 数量及已结算金额/是否待结算。直接读取 Replacement plan 也返回相同 `phase`、`progress` 和 `cost_summary`，使页面轮询、刷新和重新打开后保持同一进度。投影不得包含 source identity、target、Dataset、remote Run、Manifest、Schema、Prompt 或上游错误；存在未终态任务时优先显示该任务，否则保留最近终态结果。

Candidate 同时投影 `binding_proof_count`、`binding_required_count` 与安全 `compatibility_issue_code`，用于区分“字段已适配但仍缺当前来源证明”和“Candidate 已阻断”。公共原因只允许 `output_sample_required|binding_proof_incomplete|route_binding_missing` 或既有安全运行状态码；不得把缺少 Binding 证明误写成 Actor 故障，也不得把 `blocked` 显示成等待样本。商城名称、slug 或展示资料变化不得切断已付费证明：Candidate 内部身份固定使用 Provider 的 immutable Actor ID，并继续单独保存公开 slug/name 供 UI 展示；exact Build、Input/Output Schema hash 不变时可复用既有证明，任一 identity 漂移则重新验证。

## 字段映射补充合同（2026-08-29）

字段 AI 按 X、Instagram、YouTube Route 分别使用发布目标、Actor 类型、输入/输出别名和错 Route 类型；共同最小合同为稳定 ID、原文 URL、发布时间、目标身份及 `title|text` 至少一个，缩略图/图片和展示作者是可选增强。评论、字幕、关注关系或纯资料 Actor 只报告错 Route；嵌套内容、命名 Dataset、相对时间、Schema 不完整和可由目标派生的身份使用独立安全缺口并保持待处理。对应公共 `mapping_issue_code` 新增安全枚举 `wrong_actor_type|nested_content_items|named_dataset_required|output_schema_incomplete|target_identity_derivable|relative_published_at`，不得返回模型解释、Schema 或上游原始错误。YouTube 额外确定性支持 `maxItemsPerUrl`、大小写视频字段和常见缩略图；视频行未重复返回频道 ID 时只由 YouTube Adapter 覆盖注入已规范化的 `target.native_id` 并再次 exact 核验。

YouTube 身份派生最终使用规范化的 `target.canonical_url` 并按 URL exact 核验，取代前述 `target.native_id` 方案，因此 channel ID URL 与 handle URL 共用同一合同。

## Binding 自动对账（2026-08-25）

Binding readiness 采用本地自动对账。创建、订阅启用、Route Candidate replacement apply 与 Worker housekeeping（每 workspace 每周期最多 100 条）都会检查当前 target 指纹、当前 active/standby 的已保存 Manifest 与 Adapter 输入兼容性；同一 Binding version 的 settled `valid_nonempty` Probe 也可作为替代证据。该检查不联网、不创建 Job/Attempt、不调用 Actor、AI 或通知。pending 成功转为 ready；只有存在 enabled subscription 且 Route 允许执行时，来源才自动启用。Binding 显式 disabled 永远保持 disabled。

`POST /api/admin/apify-routes/{route_id}/v2-bindings/reconcile` 只接受 Route generation、无确认短语，返回有界 checked/verified/enabled/blocked 计数；详情为每条 Binding 仅返回安全来源名、来源启用状态、启用订阅数和 `ready|eligible|blocked|disabled` 加稳定 reason，不返回 target、Manifest、Actor/Build 或远端标识。旧 `v2-bindings/verify` 保持需要确认短语的兼容 alias，只处理 pending Binding，并在没有可证明项时返回既有 409。本节取代后文的“管理员手动核验后启用”描述。

本模块描述 ActorOps v2 数据面和单轨控制面的已实现边界。Catalog 来源的创建、修改、禁用、调度、抓取和 Feed 发布只使用 v2 Binding/Route；现役 Route list/detail、候选、Binding、Attempt、Discovery、Maintenance、Replacement、来源新鲜度、自动修复、商城元数据、头像展示映射和安全执行事件也只读取 v2 或脱敏 Operation Log。浏览器只请求 schema-2 Route 和向后兼容 schema-3 执行事件接口，显示 `active|disabled`，并将 migration-required、unavailable 与 v1-retired 作为独立安全状态。v1 Pool/Canary/Freshness/Discovery/X profile 管理 URL 均以已认证的稳定 410 `actorops_v1_retired` 响应，不进入 v1 service、表或 Job；保留的兼容 URL 只实现等价 v2 Discovery、Candidate 切换、Route cap 与 Binding 启用。`ACTOROPS_V2_ENABLED` 已删除；global 36 是当前 ActorOps schema 门，缺失时仅 ActorOps 局部返回 migration-required。global 31–35 依次保留为 resilience、系统设置、稳定控制环、Dataset 重验与私有 InputPlan 前置，旧 ActorOps v15 只由历史 migration、审计和离线 retirement 工具访问，不再是现役来源、Admin API、Worker 或前端的授权事实。

平台来源必须有当前 v2 Binding，缺少 global 36 时只让该 ActorOps 来源返回 migration-required，普通 RSS/GitHub 不受影响。Route `active` 使用 v2 Active、Standby、LKG；`disabled` 不得回退 v1，X/Instagram 返回稳定的非重试 blocked，YouTube 仅可使用 Adapter 明确声明的免费、公共网络受控 RSS fallback，且不创建 Attempt 或远端 POST。历史 `shadow` 只在 global 30 离线迁移中归一为 `disabled`，不是 Domain、schema 或 UI 状态。v2 Admin 入口不由 feature flag 选择语义；缺少当前 marker/shape 固定返回 503 `actorops_v2_migration_required`，其他读取故障固定返回 503 `actorops_v2_unavailable`。

Phase 6 已将 Worker 收为单轨：白名单只包含四种 v2 ActorOps Job；`apify_actor_discovery`、`apify_actor_validation`、`apify_actor_canary_batch` 与 `apify_actor_freshness_check` 不会被 claim、stale lease recovery 或 handler 执行。仅 `queued + attempts=0 + started_at IS NULL` 的这四种历史 Job 可在 `fetch_jobs` 事务内原子取消，并写稳定原因 `actorops_v1_retired`；其余可能已启动、关联 Run 或费用未知的 Job 保持隔离，等待离线 retirement 工具。v1 ActorOps schema 不再阻断普通 RSS/GitHub、source fetch、user feed refresh 或 Worker startup；当前 v2 schema 缺失只在 v2 Job 执行时返回 migration-required，且不会触发远端 POST。此段取代上段中“Worker 全面单轨化仍后续”的描述。

Phase 7A 的 `scripts/retire_actorops_v1.py` 是全局 v1 退役收敛入口。`status` 只返回 v1 Job/Discovery/Validation/Batch/Stage/Attempt/Run、unknown-start、未结费用、旧 standing authorization、shadow Route 与仍启用的 v1 来源的脱敏计数；`snapshot` 需要显式 API/Worker 已停和 heartbeat 安全窗，创建 `0600` SQLite backup 与不含 target、Secret、Manifest、remote Run/Dataset ID 的 receipt（代码 SHA、数据库 hash、schema shape 与 blocker counts）。当唯一剩余 blocker 是终态历史 Attempt/Validation/Batch item/Batch 的聚合派生字段时，先用 `scripts/finalize_actorops_v1_historical_costs.py`：`scan` 仅从本地 shared Run ledger 创建加盐 opaque、`0600` evidence；只有一个最终 Run（无 remote ID 时还必须是无 Dataset、零预留、零实际的 `start_rejected`）或同一链的已最终子项能精确导出金额时，`snapshot/apply/verify` 才在停服务/heartbeat 过窗、receipt hash 和 SQLite CAS 下补齐缺失的 `actual_cost_usd|cost_usd=0` 与 `cost_final=1`。完整 settled 子项总额小于 Batch 中既有的非空历史总额时，只保留该既有总额并补 final 派生位；总额小于子项或有任何不一致/多 Run/非终态事实仍阻断。它绝不联网、POST、重写非空金额、改动 Run或重开状态。随后 retirement `apply` 重验 receipt/数据库 hash 和所有 blocker：它只取消 `queued + attempts=0 + started_at IS NULL` 的四种 v1 Job，关闭旧 Discovery/Freshness standing authorization，默认将 shadow Route 改为 disabled，并只在操作员给出**精确**数量时隔离仍启用的 v1 source 或已 claim 的 v1 Job；unknown-start、任何未结费用和其他非终态 v1 事实不可豁免。`verify` 重验 receipt/hash、schema shape、integrity、foreign keys 和在线 blocker；历史表、费用与已隔离事实都保留，脚本不联网、不调用 Actor/AI、不 DROP 表或重写历史费用。Phase 7B1 的 global 30 是独立的最终 Route/Binding 重建迁移，安装前仍须先完成这些离线 blocker 检查。

1. v2 Route 身份继续使用 `platform + target_type + capability`。每个已登记 tuple 必须绑定一个独立 `ActorRouteAdapter`；未知 tuple 在 Job、数据库 mutation、AI 或 Actor 调用前拒绝。Route 健康度按每条 `ready` Binding 的实际路径计算：主用/备用加该 Binding 的 LKG 中，排除不可运行、`confirmed_failure` 和该来源仍在冷却的 Candidate；任一 Binding 零路径则 `unavailable`，否则任一 Binding 少于两条稳定 `normal` 路径则 `degraded`，全部 Binding 均有至少两条稳定路径才是 `healthy`。没有 ready Binding 时按当前已分配路径保守计算。公共投影同时返回稳定/冷却 Candidate 数、风险/不可用/原生降级来源数和下一次 Repair 时间；2/2 是补池目标，不是来源执行硬门槛。

3. v2 统一错误分类为 `configuration|target|credential|candidate|remote_unknown|internal`。Candidate 级错误可切换 Standby；credential 错误可换 Key但不惩罚 Candidate；`remote_unknown` 禁止同一 logical attempt 再发付费 POST，只冻结对应 Attempt 与费用预留，不得修改整个 Workspace Key Pool 或阻断其他 Route、免费来源和普通 Job。
