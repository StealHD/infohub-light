# ActorOps v2 计划合同

本模块描述 ActorOps v2 数据面和单轨控制面的已实现边界。Phase 2 起，Catalog 来源的创建、修改、禁用、调度、抓取和 Feed 发布只使用 v2 Binding/Route；Phase 3 起，现役 Route list/detail、候选、Binding、Attempt、Discovery、Maintenance、Replacement、商城元数据和 Operation Events 也只读取 v2 或脱敏 Operation Log；Phase 4 起，浏览器只请求这些 schema-2 v2 接口，显示 `active|disabled`，并将 migration-required、unavailable 与 v1-retired 作为独立安全状态。Phase 5 起，v1 Pool/Canary/Freshness/Discovery/X profile 管理 URL 均以已认证的稳定 410 `actorops_v1_retired` 响应，不进入 v1 service、表或 Job；保留的兼容 URL 只实现等价 v2 Discovery、Candidate 切换、Route cap 与 Binding 启用。旧 ActorOps v15 仅由后续退役前的 Worker、历史 migration、审计和离线工具访问，不再是现役来源、Admin API 或前端的授权事实。Worker 全面单轨化与最终 v1 文件删除仍按后续 retirement phase 独立完成。

来源运行语义不再受 `ACTOROPS_V2_ENABLED` 控制：平台来源必须有当前 v2 Binding，缺少 v2 schema 时只让该 ActorOps 来源返回 migration-required，普通 RSS/GitHub 不受影响。Route `active` 使用 v2 Active、Standby、LKG；`disabled` 或过渡期遗留 `shadow` 都不得回退 v1，X/Instagram 返回稳定的非重试 blocked，YouTube 仅可使用 Adapter 明确声明的免费、公共网络受控 RSS fallback，且不创建 Attempt 或远端 POST。Phase 3 的 v2 Admin 入口同样不受该 flag 控制；缺少当前 v2 marker/shape 固定返回 503 `actorops_v2_migration_required`，其他读取故障固定返回 503 `actorops_v2_unavailable`。尚未退役的 Worker 与旧兼容接口保留各自的过渡门，最终由单轨 schema marker 取代。

1. v2 Route 身份继续使用 `platform + target_type + capability`。每个已登记 tuple 必须绑定一个独立 `ActorRouteAdapter`；未知 tuple 在 Job、数据库 mutation、AI 或 Actor 调用前拒绝。一个 ready Candidate 即允许来源获取并投影 `health=degraded`，两个或以上 ready Candidate 投影 `healthy`，零个为 `unavailable`；2/2 是补池目标，不再是数据面硬门槛。
2. 来源获取顺序固定为 Active、Standby、Last Known Good、该 Adapter 明确支持的免费原生降级。原生降级必须保持来源身份、稳定 item ID、目标验证与公共网络策略，并投影 `execution_mode=native_fallback` 和稳定 degraded reason；X、Instagram 在没有可信免费路径时明确返回 unsupported。Actor 返回可信空结果不自动改走原生来源。
3. v2 统一错误分类为 `configuration|target|credential|candidate|remote_unknown|internal`。Candidate 级错误可切换 Standby；credential 错误可换 Key但不惩罚 Candidate；`remote_unknown` 禁止同一 logical attempt 再发付费 POST，只冻结对应 Attempt 与费用预留，不得修改整个 Workspace Key Pool 或阻断其他 Route、免费来源和普通 Job。
4. Publication fence 只检查来源目标指纹、binding version 和本次实际 Candidate 是否仍 runnable；无关备用槽、assignment 顺序、Route/Key Pool generation、Discovery、维护任务或其他 Route 状态变化不得丢弃已经成功取得的内容。Candidate 成功只终结远端 Attempt，LKG/水位必须在 Feed 发布事务内通过 fence 后更新。
5. Discovery 的单调 stage 为 Store Search、Metadata、Build/Pricing/Schema、Mapping、Ranking、Persist；执行状态与 stage 分离，retry 只增加 attempt 并从当前或下一 stage 继续。Phase 4 将每个安全 cursor、exact Build/Schema hash、Candidate ID、rank 和 rejection code 以 CAS checkpoint 持久化；不保存目标、Prompt、模型原文或 Provider 原始 metadata。AI 只增强确定性代码无法完成的映射，输出必须被 exact Schema 再验证；AI 不可用或无效时保留 `mapping_pending`，不能使已经确定性通过的候选消失或让整个 Job 永久失败。Discovery 不启动 Actor、Probe、Dataset 或费用 reservation。付费 Canary 的实际输出若与该 Candidate 的 Manifest 不匹配，可对该次内存 Dataset 的无值路径/类型摘要请求一次该 Candidate 专属指针 proposal；proposal 必须只选择已观察路径，并仍由目标身份、内容、URL、时间的确定性校验通过后才固化为新 exact Manifest，不能跨 Actor/Build 复用、保存 Dataset/target 或把 AI 本身作为成功证据。
6. Attempt 同时承载 fetch/probe 与一对一远端 Run 事实，状态单向推进为 `created → starting → registered → running → succeeded|failed|cancelled`，无法确认 POST 结果时进入 `start_unknown`。generation 不得减少，任何 terminal Attempt、Discovery Job 或 Candidate Probe 不得重开。Reconciler 只扫描既有 `start_unknown|registered|running` 和费用未终结的已知 Run：它只 GET/结算，绝不 POST、abort、重试或发布 Dataset；远端成功但没有 publication proof 一律以 `actorops_reconciled_unpublished_success` 终结，不能伪造 Feed/LKG/水位。未知启动仅在精确账户空窗口证明下以零费用终结；歧义、缺失或单条读取失败保留待对账并推进安全错误，不得队头阻塞。
7. v2 站立授权默认关闭。Owner/Admin 仅可通过零费用、generation CAS 的 policy API/UI 同时启用 workspace 与 Route policy；这不会排队或启动 Candidate Probe。只有两项 policy 都已启用后，低优先级 Worker Job 才可执行一个 Candidate Probe。Probe 先免费核对公开 Actor、publisher、exact Build、input/output Schema hash 和价格，再在一个 SQLite 写事务内重验 policy/Route/Candidate/Binding generation、目标指纹、每 Route 每 UTC 日 5 次、Workspace 每 UTC 月 `$3.00`（已结算实际费用加未结预留）与本 Route 唯一未结 Probe。单次上限 `$0.05`、最多一项输出、最多一次远端启动；不调用 native fallback、不发布 Feed、不推进 LKG/水位。可信非空 Probe 可将 `static_valid` 提升为 `probationary`，两个不同目标的成功证据后可提升为 `certified`，再自动补 Standby 或原子替换一个不健康且非最后一路 Candidate；空结果只记录 no-evidence，预检/身份/预算失败不花费。最后一路绝不移除，记录 `actorops_maintenance_last_candidate_protected`；超预算、身份不确定或 Publisher 风险升级继续停在人工流程。维护账本与正常订阅抓取费用分账，不提高现有抓取单 Run 硬上限。
8. `GET /api/admin/apify-routes` 与 `GET /api/admin/apify-routes/{route_id}` 固定返回 `schema_version=2` 的直接 v2 投影，不再先构造或追加 v1 payload。detail 只公开脱敏 Candidate/Store metadata、Binding readiness、Attempt 费用/状态、Discovery、Maintenance 和 Replacement；不得公开 target fingerprint、水位、Manifest、Secret、remote Run/Dataset、idempotency 或 v1 Canary 事实。`GET /api/admin/apify-actor-events` 只读取脱敏 Operation Log 中的 `actorops_v2_*` action，不读取 v1 diagnostic event。`POST /api/admin/apify-routes/{route_id}/v2-bindings/verify` 携带 Route generation，只接受当前 source、当前 target fingerprint、当前 binding version 的 v2 确定性 Adapter/Candidate 证明，或已结算、`result_state=validated`、`valid_nonempty` 的同版本 v2 Probe；v1 Binding、Canary、Validation 或旧 target 一律不是证明。证据不足保持 pending，核验不联网、不创建 Attempt、不启动 Actor；`pending → ready` 不增加 binding version。稳定兼容 alias `pool-candidates/refresh`、`active-pool/promote`、`price-cap`、来源 support 与 Binding activate 只读写 v2 事实并遵守 CAS、权限、固定确认词、费用上限和脱敏投影合同；其他 v1 Pool/Stage/Freshness/Validation/Canary/Discovery/X profile URL 固定以非重试的 410 `actorops_v1_retired` 返回，且不列入 OpenAPI。
9. global 26 使用 `scripts/migrate_actorops_v2.py` 显式离线 migration：已有库要求停 API/Worker、跨 heartbeat 安全窗，并先让所有非终态 Job/Stage/Batch/Validation/Attempt/Run、unknown start 与未结费用在 v1 收敛；blocked 或 already-migrated 不创建 backup。唯一的旧账本恢复例外是已终态 Attempt 关联**恰好一个**带 remote ID 的已终态 Run，且该 Run 已保存最终实际费用（`charge_final=1`、`charge_actual_usd` 非空）；它可证明 Attempt 的遗失 `cost_final` 派生位，无第二 Run、无最终金额或任何歧义均继续阻断。apply 才创建 `0600` backup，从 global 17–24 只读 backfill 当前 Route、exact Candidate、Binding/LKG 摘要与 disabled maintenance policy，v2 Attempt/Discovery 保持空表，再验证 marker/checksum、table/index/trigger shape、v1 内容摘要、integrity 与 foreign keys。对于不存在 v1 binding 的既有 `apify_social` 目录来源，backfill 仅在其 `platform/kind` 能解析为已登记 RouteKey、Adapter 重新接受 target 后创建独立、确定性 ID 的 `pending` v2 binding；它的 source-v1 baseline 固定为 1，不填 preferred/LKG/水位，也不改写目录来源或旧表。已安装过旧 backfill 的库只能用 `scripts/repair_actorops_v2_catalog_bindings.py --apply` 在 API/Worker 停止和 heartbeat 安全窗后补这类缺口：工具先 dry-run，apply 创建 `0600` backup，在一个事务内只插入仍缺失的 pending binding，检查 integrity/foreign keys，失败恢复 backup；它不改变 Route mode，也不是来源调用入口。partial schema、version 26 占用和 marker/shape 不一致均 fail closed 并恢复。global 25 永久惰性，migration/runtime/readiness 均不得查询、迁移、改写或删除其表和行。fresh DB 自动安装 26；已有库缺少 26 不改变 v1 readiness。
10. `scripts/actorops_v2_cutover.py` 是唯一离线 Route mode 控制入口：`status` 只输出 marker/shape、候选/Binding readiness、v1/v2 安全摘要、Attempt/费用 blocker 与授权上限；`snapshot` 创建 `0600` SQLite backup 和无 target/Secret/Manifest 原文的证据；`transition` 默认 dry-run，只有 `--apply --expected-generation` 执行 CAS。mode 只允许 `disabled → shadow → active` 与 `active → shadow → disabled`，前进要求 API/Worker 停止、无本 Route inflight/unknown-start/未结费用且摘要一致；`active → shadow` 可先阻止新 v2 获取，遗留事实只读对账。shadow 每次只发出无值选择事件并继续 v1，绝不创建 v2 Attempt 或额外 POST；active 前需逐平台确认 CLI 输出的 `20 × runnable candidate 数 × per_run_cap_usd` 上限。X/Instagram 使用 `platform + source_key + native_id` 稳定 ID，YouTube 继续 RSS feed/video ID；本条不授予真实 migration、shadow、active 或来源调用。
11. `ActorOpsBindingService` 是在线来源 Binding 生命周期入口。ensure 解析 Adapter Registry、规范化 target、创建稳定 ID 的 version 1 pending Binding 并保持来源 disabled；等价 target 和 fetch limit、analysis mode、名称/说明/频道/topics 不增加版本。真实 target/RouteKey 变化在一个事务内写来源配置、version+1、pending，并清 preferred、LKG、target 成功状态与水位。disable/soft-delete 首次转换 version+1、保留 LKG/水位审计并清 preferred；reenable version+1 回到 pending，重新 verify 后才可原子启用来源。历史 `scripts/repair_actorops_v2_binding_readiness.py` 仅作为离线退役/审计工具保留，其 v1 proof 不得被在线 verify、来源 CRUD、调度或抓取调用。
12. 当 legacy terminal Run 的精确费用因远端历史删除而不可取得时，唯一入口是 `scripts/audit_actorops_v2_legacy_costs.py`。`status` 不写入；`scan --evidence PATH` 建立 `0600`、加盐 opaque session，每次至多 20 个已知 remote Run、只执行 authenticated GET；`--resume` 只扫描未覆盖的 Run，已记录的 `remote_blocked` 只有 `--retry-blocked` 才能替换，文件不保存 remote Run ID/cursor。200 的 `usageTotalUsd` 才能写入实际费用并终结，404 只能保留原预留/`cost_final=false` 并写 `apify_historical_cost_quarantined`，401/403/429/5xx/timeout 和 unknown-start 一律继续阻断。无 durable Run 的已终态 Attempt 只能以全额预留、独立 `apify_historical_attempt_ledger_missing` 和同一证据确认隔离；running Batch 仅在无 active Job、无非终态 remote Run 时以 `apify_historical_evidence_unrecoverable` 终态化，永不 requeue/retry/start。只有完整、无 unresolved action 且仍与 DB 精确匹配的 session 才能由不联网 `snapshot` 在 API/Worker 停止和 heartbeat 过窗后创建 `0600` backup/receipt；`quarantine` 默认 dry-run，apply 同时需要此 receipt、evidence hash、精确上限和 CAS transaction。global 26 的七表、checksum 和事实不变；迁移只排除这些精确终态 code，持续投影 historical unknown upper bound，不能把隔离视为已结算费用或真实平台切流授权。
13. global 28 `actorops_v2_operator_controls` 精确依赖有效 global 26，保存 Candidate 的脱敏公开商城快照和冻结替换计划；它不保存上游原始 JSON/README、目标、Secret、Manifest 或远端输出。已有数据库只能通过 `scripts/migrate_actorops_v2_operator_controls.py` 的只读 dry-run、`0600` backup 与显式 apply 安装，backfill 只读精确 v1 Revision 的已有安全字段且不联网。Owner/Admin 的 `GET /api/admin/apify-routes/{route_id}/v2-candidates`、免费 metadata refresh/discovery、Route price-cap CAS 及 replacement preview/authorize/apply/cancel 都在当前 v2 marker/shape 门后，不受 feature flag 控制。商城标价只读；未来一次运行 cap 只允许 `$0 < cap <= $0.20`，提高须固定确认词。替换只接受用户选择的一个 exact Candidate，依 frozen Binding 稳定顺序每次最多一条 Probe/Run；每条都要 `valid_nonempty` 和最终费用，或已有同一 exact Candidate 的完整 settled proof 才可 zero-cost ready。Binding、Route、Candidate generation、价格或槽位 drift 使计划失效；contract/identity 不匹配终止并淘汰该 revision，不自动切下一项；credential 不惩罚 Candidate，unknown start/remote unknown 只读对账后才允许新的计划。apply 不联网、不花费、旧 Candidate 仅转 inactive，且绝不删除审计事实。
