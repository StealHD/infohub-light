# ActorOps v2 计划合同

本模块描述 ActorOps v2 默认停用的数据面和后续控制面目标。Phase 5 已在 Phase 1–4 的 Domain、Repository、global 26、三类 Adapter、Runtime、Reconciler、Worker claim 隔离与可恢复 Discovery 之上实现受限站立维护；Phase 6 已增加离线切流护栏，但 `ACTOROPS_V2_ENABLED` 和全部 Route 仍默认 disabled，未执行平台 shadow 或切流。站立维护目前没有 HTTP API/UI；additive API 仍是 planned。在平台切流前，[现役 ActorOps v15](jobs-migrations-actorops.md#14-apify-actorops-v15-合同) 和 D159 的人工流程继续生效。

运行双门固定为：flag=false 时 runtime/readiness 不查询 global 26；flag=true 时 API/Worker 要求完整 global 26。Route `disabled` 继续 v1，`shadow` 只读冻结 v2 选择后继续 v1且不创建 Attempt/Actor POST，只有 `active` 才执行 v2；Phase 2 不把任何 Route 改为 active。

1. v2 Route 身份继续使用 `platform + target_type + capability`。每个已登记 tuple 必须绑定一个独立 `ActorRouteAdapter`；未知 tuple 在 Job、数据库 mutation、AI 或 Actor 调用前拒绝。一个 ready Candidate 即允许来源获取并投影 `health=degraded`，两个或以上 ready Candidate 投影 `healthy`，零个为 `unavailable`；2/2 是补池目标，不再是数据面硬门槛。
2. 来源获取顺序固定为 Active、Standby、Last Known Good、该 Adapter 明确支持的免费原生降级。原生降级必须保持来源身份、稳定 item ID、目标验证与公共网络策略，并投影 `execution_mode=native_fallback` 和稳定 degraded reason；X、Instagram 在没有可信免费路径时明确返回 unsupported。Actor 返回可信空结果不自动改走原生来源。
3. v2 统一错误分类为 `configuration|target|credential|candidate|remote_unknown|internal`。Candidate 级错误可切换 Standby；credential 错误可换 Key但不惩罚 Candidate；`remote_unknown` 禁止同一 logical attempt 再发付费 POST，只冻结对应 Attempt 与费用预留，不得修改整个 Workspace Key Pool 或阻断其他 Route、免费来源和普通 Job。
4. Publication fence 只检查来源目标指纹、binding version 和本次实际 Candidate 是否仍 runnable；无关备用槽、assignment 顺序、Route/Key Pool generation、Discovery、维护任务或其他 Route 状态变化不得丢弃已经成功取得的内容。Candidate 成功只终结远端 Attempt，LKG/水位必须在 Feed 发布事务内通过 fence 后更新。
5. Discovery 的单调 stage 为 Store Search、Metadata、Build/Pricing/Schema、Mapping、Ranking、Persist；执行状态与 stage 分离，retry 只增加 attempt 并从当前或下一 stage 继续。Phase 4 将每个安全 cursor、exact Build/Schema hash、Candidate ID、rank 和 rejection code 以 CAS checkpoint 持久化；不保存目标、Prompt、模型原文或 Provider 原始 metadata。AI 只增强确定性代码无法完成的映射，输出必须被 exact Schema 再验证；AI 不可用或无效时保留 `mapping_pending`，不能使已经确定性通过的候选消失或让整个 Job 永久失败。Discovery 不启动 Actor、Probe、Dataset 或费用 reservation。
6. Attempt 同时承载 fetch/probe 与一对一远端 Run 事实，状态单向推进为 `created → starting → registered → running → succeeded|failed|cancelled`，无法确认 POST 结果时进入 `start_unknown`。generation 不得减少，任何 terminal Attempt、Discovery Job 或 Candidate Probe 不得重开。Reconciler 只扫描既有 `start_unknown|registered|running` 和费用未终结的已知 Run：它只 GET/结算，绝不 POST、abort、重试或发布 Dataset；远端成功但没有 publication proof 一律以 `actorops_reconciled_unpublished_success` 终结，不能伪造 Feed/LKG/水位。未知启动仅在精确账户空窗口证明下以零费用终结；歧义、缺失或单条读取失败保留待对账并推进安全错误，不得队头阻塞。
7. v2 站立授权默认关闭。只有同一工作区的 enabled Owner/Admin 同时启用 workspace 与 Route policy 后，低优先级 Worker Job 才可执行一个 Candidate Probe；无 HTTP API/UI 入口。Probe 先免费核对公开 Actor、publisher、exact Build、input/output Schema hash 和价格，再在一个 SQLite 写事务内重验 policy/Route/Candidate/Binding generation、目标指纹、每 Route 每 UTC 日 5 次、Workspace 每 UTC 月 `$3.00`（已结算实际费用加未结预留）与本 Route 唯一未结 Probe。单次上限 `$0.05`、最多一项输出、最多一次远端启动；不调用 native fallback、不发布 Feed、不推进 LKG/水位。可信非空 Probe 可将 `static_valid` 提升为 `probationary`，两个不同目标的成功证据后可提升为 `certified`，再自动补 Standby 或原子替换一个不健康且非最后一路 Candidate；空结果只记录 no-evidence，预检/身份/预算失败不花费。最后一路绝不移除，记录 `actorops_maintenance_last_candidate_protected`；超预算、身份不确定或 Publisher 风险升级继续停在人工流程。维护账本与正常订阅抓取费用分账，不提高现有抓取单 Run 硬上限。
8. 现有 `/api/admin/apify-routes*` 在切流期作为兼容 facade，响应只 additive 增加 `health`、`active_candidate`、`standby_candidates`、`last_known_good`、`last_success_at`、`degraded_reason` 和 `maintenance_policy`。v2 新增 `GET|PATCH /api/admin/apify-maintenance-policy`、`GET|PATCH /api/admin/apify-routes/{route_id}/maintenance-policy`，以及 `POST /api/admin/apify-candidates/{candidate_id}/probe|activate|disable`；mutation 必须携带对应 policy/Route/Candidate generation 和幂等键，仍使用统一 envelope、Owner/Admin 权限、CAS 与稳定安全错误码。Probe 只有在已启用站立授权且原子预算检查通过时免逐次确认，否则回到现役人工付费流程；activate/disable 不得绕过最后一路保护。Batch/Stage 接口必须先完成一个兼容周期和负向测试才能退役。
9. global 26 使用 `scripts/migrate_actorops_v2.py` 显式离线 migration：已有库要求停 API/Worker、跨 heartbeat 安全窗，并先让所有非终态 Job/Stage/Batch/Validation/Attempt/Run、unknown start 与未结费用在 v1 收敛；blocked 或 already-migrated 不创建 backup。apply 才创建 `0600` backup，从 global 17–24 只读 backfill 当前 Route、exact Candidate、Binding/LKG 摘要与 disabled maintenance policy，v2 Attempt/Discovery 保持空表，再验证 marker/checksum、table/index/trigger shape、v1 内容摘要、integrity 与 foreign keys。partial schema、version 26 占用和 marker/shape 不一致均 fail closed 并恢复。global 25 永久惰性，migration/runtime/readiness 均不得查询、迁移、改写或删除其表和行。fresh DB 自动安装 26；已有库缺少 26 不改变 v1 readiness。
10. `scripts/actorops_v2_cutover.py` 是唯一离线 Route mode 控制入口：`status` 只输出 marker/shape、候选/Binding readiness、v1/v2 安全摘要、Attempt/费用 blocker 与授权上限；`snapshot` 创建 `0600` SQLite backup 和无 target/Secret/Manifest 原文的证据；`transition` 默认 dry-run，只有 `--apply --expected-generation` 执行 CAS。mode 只允许 `disabled → shadow → active` 与 `active → shadow → disabled`，前进要求 API/Worker 停止、无本 Route inflight/unknown-start/未结费用且摘要一致；`active → shadow` 可先阻止新 v2 获取，遗留事实只读对账。shadow 每次只发出无值选择事件并继续 v1，绝不创建 v2 Attempt 或额外 POST；active 前需逐平台确认 CLI 输出的 `20 × runnable candidate 数 × per_run_cap_usd` 上限。X/Instagram 使用 `platform + source_key + native_id` 稳定 ID，YouTube 继续 RSS feed/video ID；本条不授予真实 migration、shadow、active 或来源调用。
11. 当 legacy terminal Run 的精确费用因远端历史删除而不可取得时，唯一入口是 `scripts/audit_actorops_v2_legacy_costs.py`。`status` 不写入；`scan --evidence PATH` 建立 `0600`、加盐 opaque session，每次至多 20 个已知 remote Run、只执行 authenticated GET；`--resume` 只扫描未覆盖的 Run，已记录的 `remote_blocked` 只有 `--retry-blocked` 才能替换，文件不保存 remote Run ID/cursor。200 的 `usageTotalUsd` 才能写入实际费用并终结，404 只能保留原预留/`cost_final=false` 并写 `apify_historical_cost_quarantined`，401/403/429/5xx/timeout 和 unknown-start 一律继续阻断。无 durable Run 的已终态 Attempt 只能以全额预留、独立 `apify_historical_attempt_ledger_missing` 和同一证据确认隔离；running Batch 仅在无 active Job、无非终态 remote Run 时以 `apify_historical_evidence_unrecoverable` 终态化，永不 requeue/retry/start。只有完整、无 unresolved action 且仍与 DB 精确匹配的 session 才能由不联网 `snapshot` 在 API/Worker 停止和 heartbeat 过窗后创建 `0600` backup/receipt；`quarantine` 默认 dry-run，apply 同时需要此 receipt、evidence hash、精确上限和 CAS transaction。global 26 的七表、checksum 和事实不变；迁移只排除这些精确终态 code，持续投影 historical unknown upper bound，不能把隔离视为已结算费用或真实平台切流授权。
