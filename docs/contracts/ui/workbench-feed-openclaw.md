The active trace is one line by default, may expand, and folds after completion into `已完成 N 个步骤 · Ns`; it exists only for the current page session. Without event capability the immediate local row remains. Stopping before the first delta produces `已停止，未生成回答`; stopping later preserves the partial answer and marks it stopped.
- Reconnection feedback lives beside the composer as `连接中断，正在重连 · 第 N 次`, keeps the draft and exposes a retry after terminal failure. A user who has scrolled upward is never forced back to the live edge; an explicit `有新回复 ↓` control appears instead. The textarea follows the single-shell 80–180 px rule. While an IME composition is active, or the native Enter reports `isComposing` or WebKit key code 229, Enter is reserved for candidate confirmation and never prevents default or sends; outside composition, Enter sends once and Shift+Enter inserts a newline. The empty state is a borderless local `PromptSuggestion` with a heading, the existing explanation and three full-width labelled starter rows; each row includes a concise description and icon, only fills and focuses the composer, and never sends automatically.
- The composer runtime row places a compact circular context-use indicator immediately before the model control. Its visible and hover/focus values use compact `k` notation with at most one decimal, while the accessible label also includes percentage. It exact-matches the already stored session key against `sessions.list` and `sessions.changed`, accepts only positive numeric totals whose `totalTokensFresh` is not false, and never adopts another session or estimates missing/stale capacity. Untrusted, stale, malformed, or mismatched data renders a neutral ring labelled `暂无可信用量`; the Agent header does not duplicate model, attachment or context data in a background-information popover.
- Connected model choices come only from `models.list(view=configured)` and the active Agent/session returned by `agents.list` and `sessions.describe`. Bare catalog IDs are normalized to canonical `provider/model` IDs before comparison and before `sessions.create`. The single model menu groups its second-level model entries under first-seen provider headings and preserves Gateway order within each provider. Compact runtime controls separately display exact-session context use, the model verified from `sessions.describe`, and the active thinking level, never optimistic browser values. The model trigger is content-sized but never wider than 180 px; its visible name ellipsizes while its accessible name preserves the complete model name. Its upward popover is at most 280 px wide and 360 px high (or the safe viewport maximum), has no outer scrolling, and keeps scrolling within the `ListBox`; the thinking control remains intrinsically sized and the fixed send/stop action stays visible at the 320 px rail minimum. Model switching creates a child session with `sessions.create({parentSessionKey,fork:true,model})`, verifies the returned session model, and only then replaces the locally stored session key; failure archives the unusable branch best-effort and preserves the original conversation. An overlong conversation offers an explicit blank-session fallback instead of silently clearing history. Selectable thinking levels come only from the exact model metadata or the exact current `sessions.describe` result; Agent-level levels never fill a missing model capability. `reasoning=false` or missing verified levels leaves a disabled `自动` control with an explanation. A compatible verified model fork preserves the current per-conversation choice only when the new verified options still contain it; otherwise it returns to `自动`. `chat.send.thinking` is per request, `自动` omits the field, a new blank conversation resets it, and retry always reuses the original send snapshot. Neither path requests `operator.admin`, calls model/thinking `sessions.patch`, or changes the OpenClaw global default.
- The connected transcript uses the 400 px default Agent rail as its density reference: messages have no bubble background, card radius, or directional indent; a 12 px decorative timeline and 9 px gap preserve the body width at the 320 px minimum. Each turn renders the exact role name `你` or `OpenClaw`, followed immediately by its local time, then a `type-chat` body. Today uses `HH:mm`, older messages use `MM-DD HH:mm`, the full local timestamp is exposed on `<time>`, and missing/invalid timestamps are omitted. A streaming assistant timestamp is fixed at its first visible delta. Only bare `http(s)://` URLs and `[label](http(s)://…)` are linkified, always in a new tab with `noopener noreferrer`; other Markdown, HTML, `javascript:` and `data:` text remains inert plain text.
- The conversation panel and every descendant are horizontally bounded. Messages, URLs, code and model labels soft-wrap or ellipsize; no chat, context, selector, setup command, Drawer, or Bottom Sheet surface uses horizontal scrolling. The setup form keeps connection authorization and paired-device reconnect in one equal-column action row; labels may wrap inside their button at the 320 px rail minimum. The send control changes in place to a labelled circular stop control; abort keeps the partial assistant reply and marks it stopped, while abort failure restores the control without discarding text.
- Gateway bootstrap token or dashboard address exists only in the connection form state and is cleared after a successful connection. New browser authorizations request only exact `operator.read + operator.write + operator.pairing`; legacy exact read/write credentials remain valid for ordinary reconnect, while every broader, incomplete, or otherwise different profile is rejected. The browser stores only a non-exportable Ed25519 private key, approved device token/scopes, and session key in IndexedDB, isolated by Inteliscope user and normalized Gateway URL. After exact-scope negotiation the paired identity/device token is saved before session initialization, and a newly created session key is saved immediately before tools/history/runtime loading. The browser never uses `sessions.list` to guess an old label and never automatically deletes, archives, renames, or adopts an existing session. Logout disconnects and clears the session transcript. When a pairing exists, `忘记此浏览器` is a neutral Unplug icon with an above-anchored Tooltip rather than a permanent danger button. It still requires confirmation, removes only the stored identity through `device.pair.remove`, and clears all matching local transcripts then IndexedDB only after server success or an already-missing device response; only the final confirmation is a filled danger action. For a legacy read/write credential, this explicit action first requests the exact current three-scope profile with its stored identity/device token so Gateway can create a `scope-upgrade` request; the UI shows the validated request ID and approval command, retains all local recovery state, and completes removal only when the user retries after approval. Every other failure also retains local recovery state.
- Gateway connection state is derived only from WebSocket state; tool availability is independently derived from `tools.effective`, and credentials, an active delegation, or `last_used_at` imply neither. The Agent header uses one compact `StatusIndicator` with a visible idle, processing, reconnecting or failure label, while running traces, reconnect guidance and errors keep their own visible text. It does not show parallel `已连接/工具可用` pills. Tool-unavailable guidance remains local to setup/runtime content. Origin repair guidance appends only the current Inteliscope origin to the user's existing allowlist and must never recommend `allowedOrigins:["*"]`.
- Viewers may navigate, open, search, copy, and assemble a handoff, but may not mutate Feed item state. Other role behavior follows the existing API/permission contract.
