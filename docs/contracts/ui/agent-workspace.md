# Agent Workspace UI Contract

## 1. Routes and runtime continuity

- `/agent` owns the full conversation workspace. `/agent/tasks` and `/agent/artifacts` keep that conversation mounted and open an inspector; `/agent/skills` and `/agent/automations` retain the session sidebar while replacing the center with a complete resource page. `/agents` remains Inscope assistant-connection management.
- The authenticated app shell owns one ordinary `useOpenClawChat` lifetime after the first Feed/OpenClaw activation. The runtime remains mounted across Feed, Saved, History, Subscriptions, `/agent/**`, `/agents`, account, and settings routes until logout, user change, explicit disconnect, or shell unmount. Navigating from the compact Feed rail with “在 Agent 工作台打开” changes only the route: it does not send, create a session, replace the ordinary socket, clear the draft, or abort a run.
- The compact Agent rail is limited to Feed, Saved, and History. Subscriptions keeps the ordinary runtime mounted but has no compact rail. Full Agent routes consume the same `OpenClawWorkspaceRuntimeProvider` and `WorkbenchAgentContext` without mounting another ordinary Gateway client.

## 2. Dual workspace layout and navigation

- Agent is not an ordinary Inscope navigation row. The top-left product switcher owns two peers: `Inscope — 订阅、阅读与追踪` and `OpenClaw — 对话、执行与自动化`. Desktop uses a Popover in the sidebar; mobile uses a bottom Sheet from the page header. It persists only the latest allowlisted route for each user and workspace. Switching is SPA navigation only and cannot send, create a Session, replace the ordinary socket, clear a draft, or stop a run.
- Inscope keeps 信息流、收藏、历史、订阅 and management routes. Mobile primary navigation is 信息流、收藏、订阅 plus 更多; OpenClaw is entered through the product switcher. OpenClaw replaces the whole navigation shell with new conversation, current/trusted child sessions and Worktree tasks, Skills, Automations, assistant connections, and account entry.
- At 1024 px and above OpenClaw uses one fixed 288 px session sidebar and one center workspace. At 1440 px and above an explicitly requested 360 px Context, Tasks, or Artifacts inspector docks on the right; it is closed by default and leaves at least 720 px for the center. There are no workspace resizers or persisted rail widths.
- At 768–1023 px session and inspector surfaces are left/right Drawers. Below 768 px both are bottom Sheets and the conversation composer preserves the viewport safe-area inset. No mode introduces horizontal page scrolling.
- The center Session Header contains only title, trusted branch, a compact connection/run status, and responsive workspace/session controls. Below 768 px, Context, Tasks, Artifacts, and theme live behind one More Sheet; desktop inspector icon actions expose tooltips. Conversation content is approximately 860 px wide and the Composer is at most 920 px. Ordinary messages are unframed; only public tool state, errors, and confirmations use local surfaces. The compact Feed Agent keeps its existing conversation variant and geometry.
- HeroUI Pro is only a hierarchy and composition reference. `AgentWorkspaceLayout`, conversation, list, status, empty, upload and Sheet behavior use HeroUI v3 OSS through the repository design system; no Pro code, package, asset or key enters the repository.
- The Session Header reuses `PageHeader` and the shared inset glass geometry. Its inset belongs to the inner conversation/resource scroll region, never the workspace root. Generated browser session labels display as `OpenClaw 对话` without changing server metadata or identity. A compact semantic connection indicator replaces duplicated status text; resource routes use their own page title. “使用示例” opens a read-only guide with steps and expected outcomes for each feature, including the mobile More entry; it never issues RPCs or inserts demonstration records into real resource lists.

## 3. Sessions and Worktree tasks

- A connection epoch establishes one trusted root Session. The rail and resource scope contain the root, current Session, its verified ancestors/siblings, and verified descendants whose exact `parentSessionKey` chain reaches that root. Cycles, orphans, and label/name inference are ignored. A new conversation establishes a new root; switching within the tree does not.
- Session switching is unavailable while the current session is sending, running, stopping, or updating. Switching first verifies the target runtime and preserves the existing ordinary Gateway connection; a failed switch leaves the current conversation active.
- “在新 Worktree 中执行” accepts a title, complete prompt, a Gateway-registered project, a branch returned by `worktrees.branches`, and an optional safe name. It never accepts an arbitrary host path. Creation uses `sessions.create` with `worktree:true`, the current `parentSessionKey`, `emitCommandHooks:true`, and `succeedsParent:false`.
- A successful create leaves the parent running. Create and retry intents each carry stable idempotency keys; ambiguous retries reuse the same key. When `runStarted:false`, the dialog retains the complete prompt and retries through `sessions.send` on the already-created session; it never repeats `sessions.create`. Closing or completing resets the form. Inscope does not delete, force-clean, restore, or otherwise destructively manage Gateway worktrees.
- There is no `tasks.create` UI. Any future Agent-originated `suggest_task` payload remains inert until a separately specified, server-verifiable confirmation-card protocol exists; generic tool events can never create a Session or Worktree.

## 4. Tasks and Artifacts

- Tasks are queried for the trusted root Session tree, at most 50 visible rows, with status filtering, details, and a local cancel confirmation. List/detail/cancel responses must repeat the requested Session/Task provenance. A verified task event refreshes the page; otherwise polling is limited to a visible page with a queued or running task and runs every two seconds, and event reliability resets after reconnect or root change.
- Artifact list/get/download always carries exactly one explicit session, run, or task provenance. Content and URLs travel browser-to-Gateway only and never enter Service API, Service storage, transcript, or persistent browser cache.
- Inline preview allows safe raster images and valid UTF-8 plain text, Markdown, JSON, and code up to 2 MiB. HTML, SVG, unknown MIME, or larger content is download-only. Base64 downloads are capped at 50 MiB; temporary URLs must be unexpired HTTP(S) at the normalized current Gateway origin. Object URLs are revoked after use.

## 5. Skills, Automations, and admin isolation

- Skills status is read through the ordinary connection. Management is limited to user-supplied ZIP archives, 20 MiB or the smaller Gateway limit, browser SHA-256, sequential 512 KiB chunks with verified offsets, commit-before-install, and explicit confirmation for replacement. The page only displays missing environment-variable names and never accepts their values.
- Skill details are readable before admin authorization and describe usage plus missing requirements. Disabled, unavailable to the current Agent, and missing dependencies are distinct states. The disabled state cannot itself block the enable action. Refresh failure retains trusted rows and offers a local retry; missing upload permission does not replace readable Skills with an authorization or setup panel.
- Automations support list/status/runs, disabled-by-default create, edit, enable/disable, delete, and run-now. The only payload is `agentTurn`; schedules are one-time, fixed interval, or Cron with an explicit IANA timezone; sessions are isolated and delivery is none. The UI never enables the Gateway scheduler itself and exposes no webhook, external delivery, shell, secret, or implicit enablement.
- Skill writes and Cron management use a separate memory-only admin controller. A write intent opens a temporary authorization Modal/Sheet instead of occupying the page; successful authorization only unlocks actions and never replays the original write. The controller publishes connecting/authorized/expired/disconnected/failed state, creates a temporary device/socket requesting exactly `operator.admin`, routes no chat events, exposes only the fixed Skill/Cron method allowlist, never reconnects, and closes on page unmount, Gateway URL change, network close, explicit destroy, connection failure, or ten minutes idle. Late connect completion is immediately destroyed. Token, private key, device token, chunks, URLs, and responses are not written to Service, logs, telemetry, `localStorage`, `sessionStorage`, IndexedDB, or the ordinary event router.
- Before admin authorization the user must affirm that the Gateway is personal or belongs to an independent trust domain. Shared Gateways remain ordinary-chat only. A cleanup warning directs the user to OpenClaw device management if temporary-device removal is not confirmed.
- Non-chat writes on the ordinary connection (including Worktree creation and Task cancellation) require a separate independent-trust-domain confirmation for the current connection. It is memory-only, is cleared by reconnect or URL change, and unlocks but never replays the original action.

## 6. Capability and failure states

- OpenClaw 2026.8.1 is the fixture baseline, not a version switch. Runtime availability comes only from exact `hello.features.methods`; root/snapshot/malformed method lists are ignored. Every response is strictly projected before it reaches a page. A method that is absent or not yet proven remains `unsupported` and cannot reach a write request.
- Connection generation and Session navigation epochs guard every asynchronous continuation. Stale operations cannot bind a Session, replace transcript/resource content, write the credential Vault, or overwrite loading/error state; queued Vault writes preserve the latest intent.
- Conversation, Sessions, Tasks, Artifacts, Skills, and Automations independently render loading, empty, unavailable, unsupported, forbidden, and failed states. A resource failure retains prior valid content and cannot clear the transcript, draft, session, or another resource view.
- The conversation exposes only public message content and fixed public execution statuses. Private reasoning, raw tool arguments/results, credentials, paths, untrusted errors, and confirmation material never render or persist.

## 7. Shared Composer shortcuts

- Both workspace and compact Feed composers retain their TextArea, image and model controls. At the caret, `@` or `/` after whitespace or at the start opens a non-modal, upward-first design-system suggestion surface; embedded email/URL/path symbols do not trigger. Suggestions never take textarea focus. Arrows select, Enter chooses without sending, Escape dismisses, and Tab retains normal focus traversal; IME composition and Shift+Enter retain existing behavior.
- `@` groups Skills and already-attached material titles. Material selection inserts a bounded readable title without changing attachments. `/` groups skills with exactly `skills`, `new`, `model`, `reasoning`, `worktree`, `status`, and `help`; built-in names retain their meaning. New-session confirmation preserves the draft, model/reasoning open existing controls, Worktree only prefills the existing confirmation flow, and status/help are read-only. Unknown text is ordinary chat, never native command dispatch.
- One removable selected Skill follows the user's draft across workspaces. Selection is not execution; source-snapshot mode rejects simultaneous Skill selection. Unavailable entries explain their disabled state. Invocation proof, directory isolation, send-time verification, and private-history projection are owned by the Gateway contract. Menu geometry is owned by the component matrix.
