# Decision Records D176–D200

<a id="d176"></a>
### D176 ActorOps 以 global 30 完成 v2 单轨运行面

- 决策日期：2026-08-23
- 当前状态：本地实现与定向验证完成；未部署、未执行真实 Actor/AI/付费来源、未创建 Tag。
- 决策内容：global 30 是唯一的 ActorOps 在线 schema 门。API、来源 CRUD/调度/抓取、Worker、UI 和管理兼容 alias 只组合 v2 Route、Binding、Candidate、Attempt、Discovery、Maintenance、Replacement、共享 Run/Key Pool/alerts 与脱敏 Operation Log；Route 状态只允许 `active|disabled`。缺少 global 30 时仅 ActorOps API/Job 返回 migration-required，普通 RSS/GitHub/source fetch/user feed refresh 继续工作。`ACTOROPS_V2_ENABLED`、shadow、disabled→v1、v1 Canary proof、v1 Factory/Worker handler/前端控制面均删除。新数据库直接由 Adapter Registry 创建 disabled v2 Route、Binding schema、默认 maintenance policy 与共享 alerts，不构造 v1 Service 或历史表。
- 历史边界：v1 表、global 13–28 migration 形状、费用审计与退役工具只允许离线 migration/audit/retirement 读取；不 DROP 表、不重写历史费用。SQLite authorizer 的在线 deny 集覆盖全部历史 v1 表，明确保留共享 Run、Key Pool 与 alerts。未开始且零费用的四类 v1 Job 可标记 `actorops_v1_retired`；已领取、可能启动、unknown-start 或未结费用的事实保持隔离，必须经离线工具和精确操作员确认处理。
- 费用与恢复：Attempt 的持久 logical identity、唯一键、固定窗口和一次 POST 上限继续生效。已观察 Dataset 只 GET/replay；unknown-start 只交 Reconciler GET/结算，不启动 Standby 或 native fallback；已知费用和 final 标志单调补充，不能被失败路径降级。disabled X/Instagram 不创建 Attempt 或远端 POST；YouTube 只可走 Adapter 明确声明的免费、公共网络受控 RSS fallback。
- 取代关系：本决策取代 D162、D166、D168、D171、D174 中所有 feature flag、shadow、additive facade、v1 proof、v1 fallback、旧 Pool/Canary UI/Worker 及逐平台双轨切流语义；这些记录保留为历史理由。D160 的 Adapter/局部故障域、D163 的只读对账、D167 的历史费用隔离、D169 的精确费用证明、D175 的显式 v2 Replacement 费用授权以及所有 SecretStore/费用审计约束继续有效。
- 原因：双轨运行会让同一来源的 Binding、候选、费用和远端 POST 有两个潜在所有者，导致重复抓取、旧数据回退和不透明的 v1 兼容分支。收敛为一个 schema marker、一个 v2 binding 生命周期和一次远端启动边界，能在保留历史审计的同时让普通免费来源与 ActorOps 局部故障隔离。

### D177 OpenClaw 专属架构先行，通用 Agent Core 延后

- 决策日期：2026-08-22
- 当前状态：已实施；只重构既有 OpenClaw、Remote MCP 与本地安装入口，不改变用户可见行为或运行合同。
- 决策内容：先以显式 `OpenClawChatController`、状态/Event/Port 合同、单一 Gateway Event Router、纯 Domain Projection、根 Reducer、Workbench Adapter、Remote MCP 三类 registrar 和 focused read/diagnostic/setup 模块稳定现有 OpenClaw 边界。历史 import 路径保留为显式兼容 façade，17 个 Remote MCP 工具、OpenClaw Protocol、scope、权限、数据库与部署保持不变。通用 Agent Core、capability registry、新 scope、新工具、用户配置体检、采集缺口检测、补采计划与核验、其他 Agent Adapter 延后到本重构合并并稳定后的独立分支和计划。
- 原因：当前只有一个已投入使用的 Browser Agent 适配器；在尚未稳定事件、状态、存储、Workbench 和 MCP 接缝前抽取通用 Core，会把 OpenClaw 特有协议误固化为全局抽象，并把纯结构重构扩大成 capability、授权和数据面的同时变更。先建立可执行的单向依赖与兼容 façade，后续才能用第二个真实 Adapter 需求验证通用接口。
- 兼容/边界：本决策不授权新增 Agent capability、工具、scope、数据库、迁移、ActorOps、Worker、Job、采集、AI、通知或发布操作。任何后续通用化都必须重新评估公共合同、权限、威胁边界和迁移策略，不得在 OpenClaw façade 内暗中扩展。

### D178 产品文档按用户影响维护，不以机械 diff 代替审查

- 决策日期：2026-08-23
- 决策内容：删除要求任意产品代码合并同时修改 Manual 和 Changelog 的 Test Gate。产品变更仍须人工判断用户影响：可见行为或 API 兼容性变化更新 Changelog，操作或配置流程变化更新 Manual；内部重构、测试和 CI 不产生虚假文档修改。
- 取代关系与原因：本决策取代 D057 的双源强制 diff 门禁，不改变两份文档作为用户说明来源的职责。文件修改不能证明内容已被有效审查，反而会诱发无意义的 Reviewed 标记；将判断收回到变更评审，保留有实际用户价值的文档更新。

### D179 OpenClaw 订阅覆盖全部用户来源且付费平台先建立停用绑定

- 决策日期：2026-08-23
- 当前状态：本地实现与定向验证完成；未部署、未执行真实 Actor/AI/抓取、未创建 Tag。
- 决策内容：“所有源”分为两层。任何当前用户可见且启用的目录来源都可通过既有 `mode=existing` 订阅，不按存储类型设白名单；新建并订阅覆盖 RSS/Website、Bilibili、YouTube channel、GitHub release/user、Reddit subreddit/user、Telegram channel、Hacker News、X profile 与 Instagram profile。Agent 公开类型保留兼容别名，规范新类型为 `github_user`、`reddit_user`、`instagram`、`hackernews`；通用 `apify` 仍只允许订阅既有可见来源。OpenBB 与 OSS Insight 尚未产品化为用户目录来源，不在本阶段伪装成可创建来源。
- 事务与费用边界：X/Instagram 的 apply 在同一 `BEGIN IMMEDIATE` 中创建 private source、用户订阅和 ActorOps v2 Binding。Binding 固定从 `pending` 开始，source 与 schedule 保持 disabled，subscription 关系可以 enabled；该事务不创建 Attempt/Job，不执行抓取、Probe、Actor POST、AI 或通知。管理员必须在 Web ActorOps 中完成既有核验与启用流程，OpenClaw 不获得 activation、费用或额外 scope。Binding 创建失败时业务行全部回滚，proposal 保持 pending 并返回稳定的暂不可用错误。
- 兼容与输入：Remote MCP 仍精确为 17 个工具，认证、scope、proposal snapshot v2、十分钟过期、逐来源 prepare/精确确认/apply 和数据库 schema 均不变。X/Instagram、GitHub user 与 Reddit user 只接受确定性的公开账号名、`@handle` 或官方主页；裸 `@handle` 未说明 X/Instagram 时由 Skill 询问一次，不猜测、不开放网页发现。YouTube 和 Bilibili 继续使用各自既有的受控解析流程。
- 架构边界：Agent 扩展类型与规范化归 `agent_source_extensions.py`，核心 `source_type_registry.py` 保留兼容 façade；Web 与 MCP 共用 `services/actorops/source_lifecycle.py`。本决策是 D177 明确要求的后续独立 capability 切片，不改变 Browser OpenClaw event/state 架构，也不引入通用 Agent Core。

### D180 系统运行参数采用 typed workspace override 与独立 Admin MCP 授权

- 决策日期：2026-08-24
- 当前状态：本地实现与定向验证完成；合并、推送、global 31 生产迁移和 VPS 发布由用户另行执行。
- 决策内容：把 21 项非秘密容量、Job、保留、存储和共享采集参数收口到唯一 typed registry；解析顺序固定为 workspace DB override、既有环境变量 alias、内置默认。global 31 只保存 override/generation 与十分钟 proposal，fresh DB 自动建立，已有数据库必须停 API/Worker 后显式备份迁移。Web `/settings/system` 与 Remote MCP 共用 preview、精确确认、单次消费和 generation CAS；运行时在对应 admission、新 Job、失败、维护、快照和采集边界热加载，不要求重启。
- 授权与隔离：新增 `system_settings_write` access、`inteliscope:system-settings:write` scope 与默认关闭的 `HORIZON_REMOTE_MCP_SYSTEM_SETTINGS_WRITES_ENABLED`。它只允许实时 Owner/Admin，和 read/subscription-write/workspace-diagnostics 相互独立，既有令牌不升级。Remote MCP 总工具数从 17 增至 20；系统连接只看 13 个读工具加 3 个系统工具，不获得订阅写入。
- 安全与非目标：密钥、Token、端点、数据库路径、Actor 费用/启用、任意环境变量和直接执行动作永久排除。日志只记 canonical changed key、数量、generation、proposal/result/request ID，不记值、alias 或确认短语。该能力不调用抓取、Actor、AI、通知，不改变付费授权边界。
- 取代关系：本决策取代 D177/D179 中“Remote MCP 精确 17 工具”和“配置工具一律不注册”的旧枚举；其 OpenClaw 专属模块边界、订阅 proposal、来源费用隔离和不引入通用 Agent Core 的其余约束继续有效。
