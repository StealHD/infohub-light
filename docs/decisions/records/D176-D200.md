### D176 ActorOps 以 global 30 完成 v2 单轨运行面

- 决策日期：2026-08-23
- 当前状态：本地实现与定向验证完成；未部署、未执行真实 Actor/AI/付费来源、未创建 Tag。
- 决策内容：global 30 是唯一的 ActorOps 在线 schema 门。API、来源 CRUD/调度/抓取、Worker、UI 和管理兼容 alias 只组合 v2 Route、Binding、Candidate、Attempt、Discovery、Maintenance、Replacement、共享 Run/Key Pool/alerts 与脱敏 Operation Log；Route 状态只允许 `active|disabled`。缺少 global 30 时仅 ActorOps API/Job 返回 migration-required，普通 RSS/GitHub/source fetch/user feed refresh 继续工作。`ACTOROPS_V2_ENABLED`、shadow、disabled→v1、v1 Canary proof、v1 Factory/Worker handler/前端控制面均删除。新数据库直接由 Adapter Registry 创建 disabled v2 Route、Binding schema、默认 maintenance policy 与共享 alerts，不构造 v1 Service 或历史表。
- 历史边界：v1 表、global 13–28 migration 形状、费用审计与退役工具只允许离线 migration/audit/retirement 读取；不 DROP 表、不重写历史费用。SQLite authorizer 的在线 deny 集覆盖全部历史 v1 表，明确保留共享 Run、Key Pool 与 alerts。未开始且零费用的四类 v1 Job 可标记 `actorops_v1_retired`；已领取、可能启动、unknown-start 或未结费用的事实保持隔离，必须经离线工具和精确操作员确认处理。
- 费用与恢复：Attempt 的持久 logical identity、唯一键、固定窗口和一次 POST 上限继续生效。已观察 Dataset 只 GET/replay；unknown-start 只交 Reconciler GET/结算，不启动 Standby 或 native fallback；已知费用和 final 标志单调补充，不能被失败路径降级。disabled X/Instagram 不创建 Attempt 或远端 POST；YouTube 只可走 Adapter 明确声明的免费、公共网络受控 RSS fallback。
- 取代关系：本决策取代 D162、D166、D168、D171、D174 中所有 feature flag、shadow、additive facade、v1 proof、v1 fallback、旧 Pool/Canary UI/Worker 及逐平台双轨切流语义；这些记录保留为历史理由。D160 的 Adapter/局部故障域、D163 的只读对账、D167 的历史费用隔离、D169 的精确费用证明、D175 的显式 v2 Replacement 费用授权以及所有 SecretStore/费用审计约束继续有效。
- 原因：双轨运行会让同一来源的 Binding、候选、费用和远端 POST 有两个潜在所有者，导致重复抓取、旧数据回退和不透明的 v1 兼容分支。收敛为一个 schema marker、一个 v2 binding 生命周期和一次远端启动边界，能在保留历史审计的同时让普通免费来源与 ActorOps 局部故障隔离。

### D180 X 账号订阅默认排除断上下文回复

- 决策日期：2026-08-24
- 当前状态：本地实现与定向验证完成；未执行真实 Actor、付费抓取、历史修复或部署。
- 决策内容：`x/profile/items` 的用户内容语义收口为非回复帖子流。X Adapter 先以完整 Dataset 执行既有 immutable Manifest、目标身份和 control-row 校验，再仅凭显式回复布尔值、父帖关系或精确 reply 类型移除回复，并重新映射剩余行，使回复不占用最终 `max_items`、不成为最新 item、也不推进来源水位。全为回复的可信 Dataset 是 `valid_empty`；引用、转发和无法由结构化字段判断关系的帖子继续保留。
- 证据边界：`replyCount` 只是互动量，正文以 `@` 或 `RT` 开头也可能是普通帖子，二者都不能作为过滤依据。输出过滤不能先于 placeholder/demo/error/control 校验，避免恶意或漂移行借回复标记伪装成合法空结果。Actor 输入支持关闭回复时可由 exact Schema/Manifest 另行优化，但不能成为唯一保证。
- 兼容与历史：本变更不增加 source config、API 字段、数据库 schema 或 migration，不改写现役 Candidate Manifest，也不重新抓取、删除或重写已有 Feed/History。当前及未来 Candidate 都在同一 X Adapter 边界执行该规则；其他平台与通用 Runtime 不增加平台分支。
- 原因：回复脱离父帖后在当前单卡 Feed 中缺少必要语境，却会占用付费抓取条数、分析和通知名额。把关系判断留在平台 Adapter，并让完整合同校验先于过滤，可以在不扩大权限、费用和历史写入范围的前提下提升 X 订阅信噪比。

### D181 ActorOps 用来源级交叉验证、异步 repair 与安全执行链路维持健康

- 决策日期：2026-08-24
- 当前状态：本地实现与定向验证完成；未部署、未执行真实 Actor、付费抓取或迁移。
- 决策内容：global 31 新增来源×候选新鲜度、每来源单一未终态 repair 和安全执行事件。只有自然调度连续三次同一候选 `no_advance`，下一周期才优先使用备用交叉验证；备用推进时只来源级冷却原候选六小时并设新的来源首选，备用同样无推进确认没有新内容。24 小时内两个不同来源确认后才允许全局降级，且永不自动移除最后一路。全部候选已结算失败时当前 Job 保持失败、Feed/水位保持不变，异步 repair 在现有 Owner/Admin 站立授权、每 Probe `$0.05`、每 Route 每日 5 次、Workspace 每月 `$3.00` 内发现、探测并临时补位；未知费用、无授权、预算不足或无候选只记录稳定阻断码。
- 可观测性与边界：执行事件关联原 Job、控制 Job、Route/source/Candidate/repair，记录候选选择、启动、注册、结算、结果、切备和 repair 的稳定阶段、原因码、计数与最终费用，数据库保留 30 天并镜像到脱敏 JSONL。`GET /api/admin/apify-actor-events` schema 3 仅 Owner/Admin 可按 Job 等安全关联读取；不保存或返回目标、输入、正文、密钥、远端 Run/Dataset 或上游原始错误。任一 trace sink 失败不改变业务结果。
- 原因：单次 `no_advance` 无法区分真实静默和上游缓存，立刻全局替换会把一个来源的偶发差异扩大为整条路线的风险；同样，在费用或授权未知时“自动重试”会导致不可审计的重复付费。把判断限定到自然周期和来源级证据、把修复放到已有授权 Worker、把事实串回原 Job，既保证可解释也保留付费边界。

- 决策日期：2026-08-24
- 当前状态：实现与定向 API/UI 验证完成；未执行真实抓取或外部请求。
- 决策内容：`RSSHUB_ACCESS_KEY` 保持固定运行用途，不成为可搜索、可误关联的通用 `SecretRef`。Owner/Admin 只在“设置 → 获取与主题”的 RSSHub 服务卡通过专用 GET/PUT/DELETE 管理其 write-only 值；状态只投影为 `secret_store`、`environment` 或 `none`，不返回真实值、任意变量名或通用密钥元数据。SecretStore 托管值可轮换或经明确风险提示删除；环境注入值只显示“环境托管”，页面返回稳定冲突而不覆盖或删除。写入/删除即时刷新 Service 环境，Worker 在下一周期重载。

### D185 付费平台订阅意图与来源就绪解耦并收紧默认获取量

- 决策内容：Web“创建并订阅”与 D179 的 OpenClaw 语义一致，允许当前用户先保存对可访问 pending/disabled 平台来源的 enabled subscription；source、Binding 和 schedule 仍保持停用，不创建 Job、Attempt、抓取或费用。该例外只由 catalog 创建订阅入口显式声明，底层 REST mutation 的默认可见性检查、事务内二次检查和其他订阅写入口仍拒绝停用来源。

### D186 平台 Binding 以本地证据自动收口并条件启用

- 决策日期：2026-08-25
