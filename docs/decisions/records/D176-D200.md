# Decision Records D176–D200

<a id="d176"></a>
### D176 ActorOps 以 global 30 完成 v2 单轨运行面

- 决策日期：2026-08-23
- 当前状态：本地实现与定向验证完成；未部署、未执行真实 Actor/AI/付费来源、未创建 Tag。
- 决策内容：global 30 是唯一的 ActorOps 在线 schema 门。API、来源 CRUD/调度/抓取、Worker、UI 和管理兼容 alias 只组合 v2 Route、Binding、Candidate、Attempt、Discovery、Maintenance、Replacement、共享 Run/Key Pool/alerts 与脱敏 Operation Log；Route 状态只允许 `active|disabled`。缺少 global 30 时仅 ActorOps API/Job 返回 migration-required，普通 RSS/GitHub/source fetch/user feed refresh 继续工作。`ACTOROPS_V2_ENABLED`、shadow、disabled→v1、v1 Canary proof、v1 Factory/Worker handler/前端控制面均删除。新数据库直接由 Adapter Registry 创建 disabled v2 Route、Binding schema、默认 maintenance policy 与共享 alerts，不构造 v1 Service 或历史表。
- 历史边界：v1 表、global 13–28 migration 形状、费用审计与退役工具只允许离线 migration/audit/retirement 读取；不 DROP 表、不重写历史费用。SQLite authorizer 的在线 deny 集覆盖全部历史 v1 表，明确保留共享 Run、Key Pool 与 alerts。未开始且零费用的四类 v1 Job 可标记 `actorops_v1_retired`；已领取、可能启动、unknown-start 或未结费用的事实保持隔离，必须经离线工具和精确操作员确认处理。
- 费用与恢复：Attempt 的持久 logical identity、唯一键、固定窗口和一次 POST 上限继续生效。已观察 Dataset 只 GET/replay；unknown-start 只交 Reconciler GET/结算，不启动 Standby 或 native fallback；已知费用和 final 标志单调补充，不能被失败路径降级。disabled X/Instagram 不创建 Attempt 或远端 POST；YouTube 只可走 Adapter 明确声明的免费、公共网络受控 RSS fallback。
- 取代关系：本决策取代 D162、D166、D168、D171、D174 中所有 feature flag、shadow、additive facade、v1 proof、v1 fallback、旧 Pool/Canary UI/Worker 及逐平台双轨切流语义；这些记录保留为历史理由。D160 的 Adapter/局部故障域、D163 的只读对账、D167 的历史费用隔离、D169 的精确费用证明、D175 的显式 v2 Replacement 费用授权以及所有 SecretStore/费用审计约束继续有效。
- 原因：双轨运行会让同一来源的 Binding、候选、费用和远端 POST 有两个潜在所有者，导致重复抓取、旧数据回退和不透明的 v1 兼容分支。收敛为一个 schema marker、一个 v2 binding 生命周期和一次远端启动边界，能在保留历史审计的同时让普通免费来源与 ActorOps 局部故障隔离。
