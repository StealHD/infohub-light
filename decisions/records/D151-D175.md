### D151 手动信息流刷新按实时角色限域，并采用协作式安全停止

- 决策日期：2026-08-13
- 当前状态：本任务分支实现与验证中；不新增 API 路径或数据库迁移。
- 决策内容：手动 `user_feed_refresh` 的来源范围由服务端在创建和 Worker 执行时分别按实时角色决定，客户端 payload 不能扩大范围。Member 只处理自己拥有且已启用的 private 来源；Owner/Admin 处理自己的 private 及自己订阅的 public/workspace 来源；Viewer 无权创建。无有效范围订阅时，在创建 Job 和记录配额前以 `409 no_enabled_subscriptions` 回滚。相同 Feed 控件在 queued/running 时转为安全停止：queued 立即取消；running refresh 只持久化 `cancelled_at` 并保留 claim，Worker 在安全边界丢弃结果，避免 Feed、Source Health、计划或通知副作用。发布事务已开始时保持原子完成。
- 原因：浏览器提交的范围提示不能作为授权来源，旧“所有启用订阅”的模糊语义会让 Member 触及公共来源；同时强杀 Worker 会破坏正在进行的网络调用、claim 和原子发布。双重角色收口与持久化停止标记把权限、队列幂等、可观测状态和副作用边界收进同一条 Job 生命周期。
- 兼容/边界：保留既有 Job API、队列 schema 与 retry 入口；summary 仅增加可选 `cancelled_at`。客户端只据此显示等待状态，不能自行判定权限或停止 Worker。收藏缓存、阅读布局和静态 bootstrap 不影响服务端授权语义。

### D152 ActorOps 固定三槽采用服务端槽位操作与证据保留

- 决策日期：2026-08-13
- 当前状态：任务分支实现与验证中；本地迁移和真实付费验证仍须按独立运行/确认边界执行。
- 决策内容：ActorOps 继续固定为 `primary/backup_1/backup_2` 三槽，不引入动态池。服务端为每槽投影新增、替换、移出以及稳定阻断原因；新增只能填第一个空槽，替换只能处理已占用槽。新增和替换沿用人工候选、一次付费验证和一次无费用原子生效，Stage/Canary 额外冻结操作槽、基础池、Route generation、候选精确 Revision/Build/Manifest、来源指纹及费用上限。验证期间 active pool 保持不变，替换成功后旧 Revision 进入 superseded 而非删除。
- 移出边界：移出使用精确确认词和 CAS，只移除 active-slot 引用并将余下槽向前压紧；Revision、Canary、费用和审计历史全部保留。unknown-start、活动 attempt/freshness/Stage、来源或 generation 冲突、以及压紧后低于 Route 实际 Actor/发布者门槛一律零写入拒绝。移出不得调用 Actor；只有仍匹配的 source Canary 证据可把 binding 降为相应 `ready_1of1|ready_2of2`，不伪造新验证。
- 迁移与界面：`apify_actor_pool_management_v22` 使用 global schema 24，离线迁移需要停 API/Worker、heartbeat 安全窗、无活跃 ActorOps Job、`0600` backup、marker/shape/integrity/foreign-key 检查及失败恢复。ActorOps 局部采用无阴影、无 sticky blur 的平面槽位与页签；pending 时锁定路由、页签和弹窗退出，390 px 自然单列。
- 原因：原有三槽池只能在抽象的升级路径中变更，管理员无法有界地移出、补回或替换单个已验证 Actor；把槽名或可否操作交给浏览器又会绕过当前任务、来源、证据和 CAS 边界。将意图限定为服务端的固定槽操作，能够复用已验证的 Stage/Canary 安全模型，同时以不硬删历史保证可审计与可恢复。

### D153 槽位重规划必须保持服务端目标可见，超额费用立即终态拒绝

- 决策日期：2026-08-14
- 当前状态：任务分支实现与验证中；不新增 schema 或放宽 Actor、来源、身份和费用门槛。
- 决策内容：持久化 `add_slot|replace_slot` Stage 的工作流投影使用其真实 goal 和 `operation_slot`，页面用该槽读取候选；已关闭的本地弹窗和 legacy 升级状态均不得改写这项服务端意图。上游终态费用若超过批准上限，validation、attempt 与 batch 以同一个安全原因终结并保留实际费用，不得卡为 running、激活 Revision 或自动重试。
- 原因：把单槽重规划误显示成旧池升级会让管理员看到与候选接口不同的操作，无法验证或纠正真实状态；将实际超额费用留在“运行中”则同时破坏账本、操作锁和费用保护。明确投影与单一终态把 UI、CAS、审计和下一次人工确认重新对齐。

### D154 ActorOps 候选先经免费可执行性证明，精确零费用中止可恢复未知启动

- 决策日期：2026-08-14
- 当前状态：任务分支实现与验证中；不增加数据库 schema，也不放宽费用、身份、内容或 unknown-start 的安全门槛。
- 决策内容：兼容 Candidate 在显示为可选择之前，必须免费证明公开可运行、非 deprecated、价格受限、精确成功 Build、可验证 input/output Schema、受控 target/max-items 输入、官方 input validation 与 Route 内容语义。X Profile 额外拒绝 reply/search/contact/其他平台等非 profile 内容语义；历史 Revision 缺少新证明时只显示稳定原因，不能进入付费计划。原始 POST 已回传 Run ID 而本地登记失败时，只有中止该精确 Run 后 GET 确认 `ABORTED` 与 `$0`，才把原 reservation 结算为终态审计行并解除锁；不得用账户列表猜测、不得把未知或非零费用当零、不得自动重发。
- 原因：把只在付费 Canary 才会失败的 Actor 放进“可选”列表会让管理员反复支付无效验证，也掩盖了输出合同或输入映射的确定性缺陷。另一方面，已知的零费用中止 Run 不是不明远端副作用；保留该精确证据并结算原 reservation，既避免永久锁死，又不牺牲重复扣费防护。

### D155 ActorOps 以认证槽位手动主用和公开 Store 质量排序收口管理员选择

- 决策日期：2026-08-14
- 当前状态：任务分支实现与验证中；不新增数据库 schema，不自动启动或重试付费 Actor。
- 决策内容：三条固定 Route 都允许管理员将已占用的备用槽设为主用。服务端以 Route generation、活动 Stage/attempt/freshness 与 unknown-start 栅栏保护该操作；确认后只原子交换现有 slot/candidate 顺序，保留 Revision、来源验证、费用与审计，不创建 Actor Run。Route 的未来单 Run 上限可在同一 CAS 边界内调整至最高 `$0.10`，不改动当前池也不主动消费额度。候选先保持所有公开性、Build、Schema、输入、内容合同、价格与身份底线；仅在通过后，才按 Apify Store 的公开评分、评分人数和使用人数稳定排序并投影给管理员，任何缺失指标均不得伪造。
- 原因：管理员需要能直接切换已验证备份来确认真实运行链路，而不应为顺序调整重新触发验证或付费。Store 的质量指标能帮助从同样安全的候选中做出更可解释的选择，但若参与安全准入或替代免费预检，会再次把热门但不可执行的 Actor 误导为可配置项。
- 兼容/边界：初配、新增、替换、移出和来源启用仍使用既有两阶段确认与证据门槛；YouTube 仍 Atom-first，Actor 只在允许的 fallback 失败路径执行。全局 `$1` 测试额度不成为产品自动消费授权，任何付费 POST 仍需此流程内的人工确认。

### D156 YouTube 以来源认证 Actor 为主、Atom 仅作失败降级

- 决策日期：2026-08-17
- 当前状态：本任务分支实现与验证中；不新增数据库 schema 或自动付费。
- 决策内容：保留 YouTube 的 RSS 来源身份、稳定内容 ID 与公开网络约束，但只有已完成来源级 Canary 的绑定可抓取。每次抓取先冻结并执行该来源的认证 Actor，按发布时间倒序保留来源设置的条数；Actor 本次失败才尝试公开 Atom/RSS，认证 Actor 的空结果不回落到 Feed。Actor 结果重新投影为 RSS 条目时必须保留 Route generation、来源、候选和水位证明，缓存与发布水位据此识别为 Actor 获取。新增或改目标的 YouTube 来源会绑定 Route；验证前允许订阅但以明确错误阻止获取。
- 原因：Atom/RSS 的网络超时、解析及上游限制曾被写成抓取成功且没有新内容，而已认证 Actor 又只在其后才有机会执行，无法提供稳定的最新订阅。把认证证据作为主链准入并将 Atom 限为同次失败降级，可让“成功”对应真实内容合同与可追溯 Actor，同时保留无费用的临时可用路径。
- 兼容/边界：已有来源不会被迁移或删除；其绑定一旦完成现有来源级 Canary 即自动使用 Actor 优先路径。每次运行仍遵守 Route 单次费用上限、冻结 Build/Manifest、身份/内容/发布时间合同和已有切备规则；本变更不创建 Canary 或周期新鲜度任务，付费验证仍需现有明确确认。

### D157 ActorOps 只向浏览器暴露已完成实测与对账的目录

- 决策日期：2026-08-18
- 当前状态：本任务分支实现与验证中；不新增数据库 schema，不自动扩大费用额度。
- 决策内容：免费 Discovery 及受控 Canary 的原始库存仅保留在服务端，用于继续筛选、失败记忆和受控实测。`pool-candidates` 的浏览器投影只包含已通过精确 Build Route Canary、所有当前启用来源的匹配指纹 Canary、且全部费用完成对账的 Actor。浏览器选择 opaque Candidate 后只执行无费用、CAS 保护的原子启用或替换；证据或 generation 变化则零写入拒绝，绝不重复调用 Actor。
- 原因：此前把“可进行下一次试跑”的内部库存当成了“可供管理员选择”的目录，导致用户在选择后才看到元数据、身份或输入合同失败，也可能误以为仍会再次付费。将实测与选择分离后，用户可见候选的语义与“现在可直接运行”一致，同时保留后台对不同平台各自执行器、输入映射、输出验证和费用规则的受控处理。
- 兼容/边界：X、Instagram、YouTube 只共用 Stage、证据、CAS 与目录编排；平台组合的执行器、输入、输出与费用策略必须预先登记，否则 fail closed。旧失败/费用/Discovery 记录保留审计，不回写成候选；选择前后的任何证据变化均不产生新费用。

### D158 ActorOps 能力矩阵统一标准主备，并免费恢复中断的既有 Canary

- 决策日期：2026-08-18
- 当前状态：本任务分支实现与验证中；不新增数据库 schema，不创建新的自动付费授权。
- 决策内容：X、Instagram、YouTube 的注册能力矩阵都显式绑定平台执行器、输入映射、输出验证、费用策略与标准门槛 `2 Actor / 2 发布者`；第三槽仍按需补充。未登记 tuple 在任何写入或调用前拒绝。Worker 在无活动 Stage 时免费收口旧 Route/binding 到该策略；活动 Stage 保留冻结的 Build、目标槽和来源证据，待其安全结算。Worker 重启后，已知远端 Run 的 validation、batch item、batch、stage 与 Job 必须一起投影为 `blocked_unknown_start`，随后只能 GET 核对原 Run/Dataset 和原费用；核对成功时续跑原审批的冻结 batch。若原 Run 已终态失败，则仅继续同一审批内尚未运行的条目，不再次 POST 已失败 Actor；仅当 Route/Profile/Stage 共同证明版本号只被该未知启动保护步骤自动加一时，才恢复冻结审批版本。若旧 Worker 已把同批零费用项误标为 `approval_stale`，只在同一证据链完整时将其重新排队；任何真实配置变更仍拒绝。重建前必须以真实运行库的残留状态完成回归演练。
- 原因：之前 YouTube 的单路 fallback 例外和重启时只更新 validation 的行为，使容量、选择目录、Stage 与 Job 互相矛盾，出现“一路显示可用、一路仍在运行”以及无法补齐备份。统一最小池与原 Run 的免费恢复把可用性、费用和 UI 真相收回到同一证据链。
- 兼容/边界：D155 的 Atom-first 描述及 D156 的 Atom 降级被本决策取代；YouTube 保留 RSS/频道 ID 仅作为来源身份，运行时只走认证 Actor。浏览器目录仍仅显示成功、对账且完成全部已启用来源验证的 Revision；用户选择不触发 Canary 或收费。网络不可读、超时或未结算继续阻断，绝不猜测成功或重新启动。

### D159 ActorOps 自动替换退役并回归免费发现与双确认

- 决策日期：2026-08-20
- 当前状态：本任务实现与验证中；不新增运行时 schema，不删除任何既有 Actor、费用或实验表数据。
- 决策内容：单槽新增/替换只使用现有 `pool-candidates/refresh → Canary plan/batch → staged activate` 链路。一次管理员动作至多创建一个免费 Discovery Job，内部最多三轮 Store 查询；付费必须先展示冻结 Actor、Route generation、逐项和批次上限并完成确认 1/2，费用终结且 Stage `apply_ready` 后仍需确认 2/2 才能改变活动池。未发布的 auto-pool HTTP、Worker continuation、循环补位、服务端代填 approval/apply 与自动生效全部退役。
- 费用与迁移边界：所有 Route 单 Run 写入与执行硬上限统一为 `$0.10`。现役 ActorOps migration 链止于 global 24；实验性 global 25 若已存在只作惰性历史证据，不参与 runtime、readiness、maintenance 或 fresh bootstrap，普通代码不得读写、迁移或删除。只有显式离线退役工具可在 API/Worker 停止、heartbeat 过窗、无 unknown-start 且费用全部终结后安全终态化遗留 auto-owned 工作；global 25 永久保留，未来 migration 从 26 继续。
- 原因：自动流程曾绕过现有双确认、缺少幂等与唯一 active 约束，并在 `$0` shortfall 下无限创建 Discovery；其费用账本同时漏记成功批次且可重复累计。复用已经具备 plan hash、approval ID、CAS、费用终态和恢复语义的现役 Stage 链，能消除第二套不完整状态机，同时保留管理员的一键免费搜索体验。
- 兼容/边界：已存在的 global 25 marker、表和历史行不删除、不回写为新候选，也不成为未来迁移前置。旧客户端访问 auto-pool 路径得到统一 404。YouTube、Instagram 与 X 的标准门槛继续为两个 Actor、两个发布者；任何真实 Actor/AI/通知调用仍只允许在既有明确授权边界内发生。
