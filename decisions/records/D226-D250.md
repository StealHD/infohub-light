# Decisions D226–D250

<a id="d226"></a>
### D226 媒体能力与内容成功分离（2026-09-20）

接受：Instagram 按媒体结构而非 Actor 作者适配；媒体缺失保留正文，不在同轮追加收费。新增通用可选媒体证据端口和私有 global 48 sidecar，后续正常抓取在原合格候选内优先已观察多图者。同任务恢复、费用与故障约束优先。Schema 展示列、真实字段定义与观察结构分别记录，不从字段缺席推断 Actor 不支持。

原因：事故样本的 Dataset 本身缺少子图；另有备用 Actor 声明了本地未解析的数组。混为抓取失败会误罚上游并追加费用，单纯换 Actor 也不能修复本地解析缺口。

兼容：旧 Manifest、Feed 媒体接口及最多 6 张缓存保持；旧库未迁移时质量未知但抓取继续。真实能力由已授权结果确认，不以文档或构造测试认证。没有生产迁移、切流或历史补图的自动授权。接口和职责以 API/架构合同为准。

<a id="d227"></a>
### D227 自动化模型选择器复用对话视觉角色（2026-09-23）

接受：个人自动化配置复用对话的模型列表和推理滑杆视觉角色。目录完整 ID 的首段作为来源，模型列表及已选值都展示来源，便于区分同名模型。选择只修改本地草稿，保存时仍提交完整模型 ID 和可选推理强度。

边界：对话选择器的即时会话切换和 Fast 开关不进入自动化配置；自动化模型目录、执行权限、测试与通知流程保持原合同。界面行为以[个人信息提醒 UI](../../contracts/ui/agent-workspace.md#个人信息提醒)为准。本决策不表示生产已部署。

<a id="d228"></a>
### D228 自动化模型不再逐项授权（2026-09-26）

接受：OpenClaw configured 模型是自动化唯一模型配置入口，无需维护额外 completion 模型白名单。接入安装和目录发现清除遗留列表，不再依赖归属记录；版本校验防止覆盖并发配置，重复同步不写配置。

原因：生产旧白名单遗漏了已配置的 senjee 模型，导致目录可选但推理被拒绝。用户明确要求所有已配置模型无需额外授权。本决策取代 D218 中按白名单归属决定是否移除、保留管理员模型列表限制的规则。

边界：个人与分析 Agent 实际可用性、全局插件启用、工具隔离及 Provider 认证继续生效。取消模型白名单不表示密钥有效，也不表示生产代码已发布。

<a id="d229"></a>
### D229 Skill 受限执行能力（2026-09-26）

接受：已开放 Skill 清单同步同时补齐受限 read；book-skill 另需 browser。read 固定 workspaceOnly，沿用 OpenClaw 对当前已解析 Skill 目录的只读例外，包含参考文件；清单收回时撤回受管能力。初次配置与既有清单重存使用同一策略。同步需核对配置及精确 Agent 已有会话的实际工具，不能只凭 eligible 声称可执行。

原因：生产 book-skill 元数据可用，但 Agent 无法读取 SKILL.md，实际对话仅调用 Feed 工具。用户明确要求仅补 Skill 能力，发送反馈由其他任务处理。此决策修订 D213 中开放清单绝不改变工具权限的边界；新增范围只含上述受管切片，不授予 Shell、文件修改、任意主机读取或其他 Skill 的执行依赖。

兼容：MCP 身份、角色、Token、其他 Agent 与发送协议不变。配置同步保留受管切片以外的工具配置；已有连接可由管理员点击“同步执行能力”补齐，无需重新绑定。Gateway 2026.9.2 的官方包代码已核对 Skill 目录读取例外；原生执行测试按实际安装包记录，不等同于生产部署或真实查书成功。

<a id="d230"></a>
### D230 个人 Agent 可使用已授权的 VPS 桌面 Skill（2026-09-26）

接受：用户明确授权个人 Agent 使用 VPS 桌面浏览器及 book-skill 的可视验证能力。为已开放该 Skill 的个人 Agent 增加 `book_desktop`，调用原生固定脚本，复用任务租约、验证码处理与断点续跑。此决策扩展 D229 的 read/browser 工具切片，不再将个人 Agent 的 book-skill 限定为受管 browser 流程。

边界：共享桌面保留其现有站点会话，不承诺 Cookie 隔离；工具从可信 Agent 与会话身份派生独立任务，只访问该任务所属标签页与当前验证码图片。各任务按桌面租约串行，不开放任意 Shell/主机文件或跨会话工具。验证码操作遵循宿主的当前确认要求。插件安装、工具可用、实际脚本调用、验证通过和最终检索结果分别记录，不以其中一项代替其余证据。
